# 2D·3D 그리기 LOD 와 최적화

사진 보드에서 사인물을 2D(원근 그림)·3D(WebGL)로 그리는 방법과, 휴대폰 메모리·속도를 지키는 규칙을 한곳에 모은 문서입니다.
기능 설명은 [features/render-3d.md](../features/render-3d.md)·[features/photo-board.md](../features/photo-board.md)에 있고, 여기에는 **층 구조, 언제 무엇을 다시 만드는지, 한도 숫자, 그렇게 정한 이유(사고 기록)** 를 둡니다.
상수를 바꾸면 이 문서의 표도 같은 커밋에서 고칩니다.

## 목표 (사용자 요구)
- 2026-10-29: "기존이미지와 3d이미지로 변환을 LOD를 접목해 사용자가 눈치채지 못하게" — 바뀌는 순간이 보이지 않는다.
- "사인물을 변경한 경우가 아니라면 기존의 저장된 이미지를 사용한다" — 같은 내용이면 다시 만들지 않는다.
- "시트처럼 2d인 경우는 3d로 변환할 이유가 없다" — 납작한 사진은 3D 를 하지 않는다.
- "2d도 이동하거나 변경하면 사라졌다 다시 나타난다" — 다시 만드는 동안에도 앞 그림을 둔다.
- 아이폰 앱(WebKit)이 메모리를 넘기면 페이지가 다시 열린다(빈 화면·스피너). 화면 크기를 넘는 그림·층을 만들지 않는다.

## 사진 LOD
- 2026-10-29 사용자: "줌인아웃을 반복하면 다운된다" → "사진도 lod 쓸수 있나?". 줌아웃하면 모든 사진이 화면에 들어와 표시 사본(휴대폰 긴 변 1600 ≈ 풀면 7.7MB)이 한꺼번에 풀렸다(사진 16장 ≈ 120MB, 3D 는 저장된 3D 그림 1280 이 더).
- 바닥 그림(`photo-img`)은 **긴 변 `THUMB_MAX`(480) 작은 그림**(`smallUrl` — 한 번에 하나씩 만들고 최근 200장 주소 기억, 이미 작으면 원래 그림). 사진이 화면에서 `화면 크기 × 기기 배율 > 480`(`needsFull`)일 때만 원래 그림(`photo-full`)을 **위에** 얹는다 — 바닥은 그대로라 바뀌는 동안 빈 화면이 없다. 3D 단계의 저장된 그림도 같다(`photo-overlay` 작은 그림 + `photo-overlay-full`).
- 테스트 `tests/e2e/photoLod.spec.ts`.

## 아이폰 방지 장치 되살림 (2026-10-29)
사용자: "2d는 줌인아웃 3d는 화면 팬에서 둘다 반복에서 나타났음 안드로이드는 잘된다. 그리고 맥북 크롬에서도 잘됨" → "혹시 실시간 업데이트 최적화 이후 벌어진 일인데" → "진행해줘".
기록을 보면 그 무렵 두 변경이 예전 아이폰 방지 장치를 없앴다: `334287b`(움직이는 동안에도 실시간 3D — 그전엔 움직이는 동안 저장된 그림, 멈춘 뒤 짓기) · `7589601`(2D 두 손가락 조작 중 원근 층 숨기기(10-21 핀치 크래시 대응)를 `will-change` 로 바꿈). 맥 크롬·안드로이드는 메모리를 바로 돌려주지만 아이폰은 늦어 반복하면 넘친다고 본다(실기기 측정은 아님).
- **휴대폰 2D 는 원근 층을 아예 안 씀**: 크게 보여도 사진마다 납작한 그림 — 긴 변 `FLAT_MAX_HI`(2048)(`flatMaxFor(phone, enough)`: 작게 보이면 1024, 휴대폰에서 크게 2048, 데스크톱에서 크게 = 사인물별 원근 층). 줌인·줌아웃 때 층을 만들고 버리는 일이 없다.
- **휴대폰 3D 는 멈춘 뒤 짓기**: 가운데 사진이 바뀌면 화면이 `LIVE_SETTLE_MS`(300ms) 멈춘 뒤에 얹는다(`liveBuildDelay`) — **지어 둔 장면이어도**(2026-10-30, 처음엔 지어 둔 장면은 바로였다). 그동안 실시간은 숨고 저장된 3D 그림.
- **휴대폰은 움직이는 동안 실시간 3D 쉼**(2026-10-30 두 번째 진단 기록 2건: 앞 사진 유지 뒤 오가는 현상은 없어졌지만 두 손가락을 대자마자 34~400ms 안에 다시 열림, 배율 9~24%): 화면(보드 위치·배율)이 바뀌면 실시간 3D 를 숨기고 그리지 않는다(저장된 3D 그림이 보임), 멈추고 `LIVE_SETTLE_MS` 뒤 다시. `334287b` "움직이는 동안에도 실시간" 이전 방식을 휴대폰에만 되돌림 — 데스크톱은 그대로. 진단 기록에 "실시간 3D 쉼/다시". 테스트 `tests/e2e/stage.spec.ts` "휴대폰 폭 3D".
- **가운데 사진 유지**(2026-10-30, `liveView(…, prev)`): 아이폰 진단 기록 7건 모두 3D, 다시 열리기 직전 가운데 사진이 두 장 사이를 15~30ms 마다(한 프레임에 두 번도) 오가며 기억한 장면을 번갈아 얹었다(핀볼 사본: 측면↔측사면, 정면↔정사선, 제스처 한 번에 10~16번). 이제 앞 사진이 아직 쓸 만하면 가운데를 차지하고 있거나 아무도 가운데를 차지하지 않을 때 그대로, 다른 사진이 가운데를 차지하고 앞 사진은 아닐 때만 넘어간다. 크롬 에뮬레이터로는 오가는 현상이 재현되지 않았다. 기억하는 장면 휴대폰 2 → **1**, 앞면 텍스처 휴대폰 1536 → **1024**.
- **버린 장면의 캔버스를 바로 비움**(`render/release.ts releaseTextures`): `texture.dispose()` 는 GPU 쪽만 — 앞면·빛 번짐 캔버스는 가비지 수거까지 남았다. 버릴 때 크기를 0 으로.
- 맥 WebKit(아이폰 13 설정) 핀볼 3D 화면 이동 20번: 그래픽 최대 223 → 184MB, 오류 없음 (가운데 사진이 거의 안 바뀐 조건이라 참고만).

## 2D LOD
- **줌아웃 = 사진마다 납작한 그림 한 장**(2026-10-29 사용자: "아이폰 앱과 크롬에서 둘다 2d에서 줌 아웃에 앱은 다시 열고 크롬은 죽었다"): 사인물마다 원근 층(`matrix3d`)이면 줌아웃 때 **모든 층이 한꺼번에 화면에** 들어와 층마다 메모리를 잡는다(위에 그려진 이름 줄·안개 층도 겹친다는 이유로 따로 층이 된다). 핀볼 휴대폰(3배): 층 31개, 층 크기 합 약 500MB.
  - 사진이 화면에서 `화면 크기 × 기기 배율 ≤ FLAT_MAX`(1024px)이면(`flatEnough`) 사인물별 구운 그림을 캔버스에서 원근으로 그려(칸 12×12, 삼각형마다 아핀 변환, 이음새 0.6px 넓힘, 외곽선으로 자름, 불투명도 0.95) **3D 변환 없는 그림 한 장**(`flat-overlay`, 긴 변 ≤ 1024, 작은 사진은 2배까지)으로 쓴다. 더 크게 보이면 사인물별 원근 층 — 그때는 사진 몇 장만 화면에 있다.
  - 구운 그림 컴포넌트는 납작한 모드에서도 굽기만 하고 주소를 알린다(`onbaked`, 그릴 것 없으면 `null`). 모두 구워지면 내용 키로 합친다(같은 키는 다시 안 그림, 최근 120장 기억). 새로 합치는 동안은 앞 그림 그대로.
  - 결과(핀볼, 2% 줌): 층 31개(약 500MB) → 화면 틀 층 5개(24MB), 사인물 그림 풀린 크기 30MB → 6MB.
- **구운 그림**(2026-10-29): 사인물의 구성 요소(글자·그림·도형)와 입힌 디자인을 긴 변 `BAKE_MAX`(1024px, 배율 최대 2배) 그림으로 한 번 그린다. 화면에는 `<img>` 하나에 원근 변환 — 확대해도 다시 그리지 않아 메모리가 그대로다.
  - 내용 키 = 배치(`layoutParts`) + 크기 + 그림 주소(구성 요소), 페이지 에셋 + 자르기 + 크기(디자인). 같으면 캐시된 objectURL 을 그대로 쓴다.
  - 굽기 전에는 DOM 층(`PartsOverlay`·`DesignFace`), 다시 굽는 동안은 **앞 그림**을 둔다 → 사라졌다 나타나지 않는다.
  - 글자 그리기는 3D 와 같은 `render/faceDraw.ts drawFaceItem` (2D 는 굵기 700).
  - 무엇이 그려졌는지는 `alt`(글자)·`data-colors`(색)로 남긴다 — 읽기 도구·테스트용.
- **두 손가락 조작 중**: 원근 층을 숨기지 않고 `will-change: transform`(`InfiniteCanvas` `.pinching`) — 움직이는 동안 지금 그림을 늘려 쓰고 손을 떼면 또렷하게 다시 그린다.
- **안개 블러**: CSS `filter: blur()` 를 사진 전체에 걸지 않는다(확대 배율로 다시 흐리게 그려 메모리가 커진다). 폭 = 표시 폭 ÷ (반지름 × 0.8), 최대 `BLUR_MAX_W` 400px 로 두 번에 걸쳐 줄인 JPEG 를 늘려 쓴다.
- **끌기는 화면에서만, 놓을 때 한 번 저장**: 사진 옮기기(`PhotoZone dragOff`)·사인물 외곽선 편집(`editing.quad`)·평면도 카드(프레임마다 한 트랜잭션)는 끄는 동안 문서(Yjs)에 매 프레임 쓰지 않는다 — 쓰면 동기화·기기 저장·파생 값 재계산이 프레임마다 돈다(2026-10-29 안드로이드).

## 3D LOD
- **저장된 3D 그림**: 사진마다 내용 키(`app.stageKey` — 사인물·카메라가 바뀌면 바뀐다)로 IndexedDB `ganpanda-derived` 에 `s3|<사진>|<키>` JPEG. 키가 같으면 다시 만들지 않는다(다시 열어도 `stageMade` 0).
  - 데스크톱: 합성 그림을 만들어 저장. 휴대폰: 합성용 WebGL 을 따로 만들지 않고 **실시간 화면에서 떠서**(`LiveStage.snapshot`) 저장.
- **실시간 3D 는 가운데 사진 하나**(`liveView`): 화면 가운데가 들어간 사진(없으면 가장 많이 보이는 사진). 그 사진에서 **화면에 보이는 조각만 화면 해상도로**(`Viewer.setCrop` — 배경 uv 와 모든 카메라 투영 뒤에 자르기 행렬). 그래서 확대해도 그림판이 화면보다 커지지 않는다.
- **겹치기**: 사진 → 저장된 그림 → 실시간 3D 를 **투명도 0.22초**로 겹쳐 나타나고 사라진다. 같은 장면이라 바뀌는 순간이 안 보인다. 가운데 사진이 바뀌는 순간엔 실시간을 바로 숨겨 엉뚱한 자리에 남지 않게 한다.
- **멀리서는 실시간 안 함**: 가운데 사진의 화면 짧은 변이 `LIVE_MIN_PX`(80px) 미만이면 장면을 짓지 않는다(줌아웃 중 장면 짓기 = 휴대폰 메모리). 160px 은 너무 높아 80px 로 낮췄다.
- **납작한 사진**(`core/stageFlat.ts needs3d`): 시트·현수막뿐(또는 분류 없는 외곽선뿐)이면 3D 단계에서도 합성·실시간 없이 2D 구운 그림 그대로.
- **장면 짓기**: 준비(`prepareScene`, 에셋 로드)와 얹기(`applyScene`)를 나누고, 짓기는 **한 줄로**(`chain`) — 겹치면 사진이 섞이고 사인물이 쌓였다(2026-10-28). 지은 장면은 사진마다 기억(휴대폰 2, 그 외 4). 데스크톱은 보이는 옆 사진을 미리 짓는다.
- **그림판 고정**: WebGL 캔버스·버퍼는 보드 화면 크기로 고정(창 크기가 바뀔 때만 다시) — 끄는 중·확대 중에도 바로 다시 그린다.
- **디자인 그림 기다림**: 최대 `LIVE_ASSET_WAIT_MS`(2.5초)만 기다리고 없이 그린다. 늦은 그림은 60초 동안 기억해 다음엔 기다리지 않는다(없는 에셋이 줄을 18초 막았다).
- **컨텍스트 잃음**: `webglcontextlost` 면 실시간을 끄고 저장된 그림·사진으로 남는다.

## 재는 방법
- **진단 기록**(2026-10-29, `crashLog.ts`·`ui/CrashNotice.svelte`): 아이폰은 웹 화면이 메모리를 넘기면 pagehide 없이 다시 연다. 돌아가는 동안 1초마다 지금 상태(단계·배율·실시간 3D 사진·지은 장면·그림판 크기·그림 수 등)와 최근 사건 30개(단계 바꿈, 3D 장면 시작·끝, 3D 그림 뜨기, 3D 화면 잃음, 두 손가락 시작·끝)를 `localStorage ganpanda.crash.live` 에 쓴다. 화면을 숨기거나 떠나면 "깨끗"으로. 다음에 열 때 깨끗하지 않은 기록이 60초(`CRASH_GAP_MS`) 안이면 화면 위에 **직전 상태**를 보여 주고 [기록 복사]·[닫기]. 테스트 `tests/unit/crashLog.test.ts`, `tests/e2e/crashLog.spec.ts`.
- WebKit 에뮬레이션: Playwright `browserName: 'webkit'`(채널 없음). 스크립트 오류가 없다고 메모리가 괜찮은 것은 아니다.
- 층 크기: Chrome CDP `LayerTree`(층 수·화면 크기), 터치: `Input.dispatchTouchEvent`.
- 프레임마다 쓰기: `project.doc.on('update')` 횟수, `MutationObserver` 로 끄는 동안 바뀌는 요소.
- 실제 아이폰 확인이 최종 — 에뮬레이터로 재현 못 한 다시 열림이 있었다.
