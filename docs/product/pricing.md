# 요금제

## 요약
기본은 무료입니다. 무료와 유료는 **한 달 제안 링크 건수**와 **제안 페이지의 간판다 표시**로 나뉘고, 유료끼리는 **동시 작업 인원(직원)**과 저장 용량으로 나뉩니다.
**고객(viewer 초대) 열람은 어떤 요금제에서도 인원에 세지 않습니다** — 제안 링크가 퍼지는 길을 막지 않기 위해서입니다. (2026-10-17 개편, 이전 표는 아래 "대체된 표")

## 상태
구현됨 — 한도·안내만. 결제는 미구현이며 `accounts.plan` 은 관리자가 바꿉니다(`free` / `basic` / `pro`, 옛 `starter` 는 베이직으로 읽음). 기준표 `server/src/plans.ts`.

## 요금제

| 요금제 | 월 요금 | 제안 링크 | 동시 작업 인원 | 저장 용량 | 제안 페이지 |
|---|---|---|---|---|---|
| 무료 `free` | 0원 | 한 달 3건 | 1명 (소유자) | 500MB | "간판다로 만든 제안" 표시 |
| 베이직 `basic` | 30,000원 | 무제한 | 2명 | 5GB | 표시 없음 |
| 프로 `pro` | 60,000원 | 무제한 | 5명 | 20GB | 표시 없음 |

금액은 부가세 포함 여부 미정. 유료 기능으로 계획 중: 팀 라이브러리, 공급사 발주 연동(프로).

## 원칙 (2026-10-17)
- **결제·계약금 수납·에스크로는 플랫폼에서 하지 않습니다.** 돈이 간판다를 거치면 시공 분쟁·환불·하자 책임이 간판다로 옵니다. 돈은 간판집 계좌로 직접, 간판다는 합의(승인 스냅샷)와 사양을 기록·전달만 합니다 → [decisions.md](decisions.md).
- 검토 중인 수익원: 구독(직원 좌석만), 문서 건당 과금(계약 확인서·주문서·허가 도면), 공급사 발주 수수료(B2B 전달).

## 규칙
- **제안 링크**: [제안 보내기]로 만든 viewer 링크(`invites.kind = 'proposal'`)만 셉니다. 보통 초대 링크(보기·편집)는 세지 않습니다. 계정의 **모든 프로젝트 합산**, 달은 UTC 1일 기준(`monthStart`). 한도에 닿으면 `402 {error:'proposal_limit', used, limit}` 이고 앱은 "무료 요금제는 제안 링크가 한 달 3건까지…"로 안내합니다(`proposal-error`).
- **동시 작업 인원(좌석)**: 계정 전체 합계. 좌석을 쓰는 사람 = 로그인 세션(소유자·멤버)과 **editor 초대**로 들어온 사람. **viewer 초대(고객·제안 페이지)는 좌석을 쓰지 않습니다.** 같은 사람의 탭 여러 개 = 1석. 초과면 `429 seat_limit`, 앱은 "동시 작업 인원 한도… 고객 열람은 인원에 들지 않습니다" 배너(`seat-limit`)를 띄우고 자리가 나면 자동 연결.
- **저장 용량**: 에셋 업로드·다운로드는 `?project=<id>` + 자격(세션 또는 초대)이 필요합니다(viewer 도 대화 첨부를 위해 업로드 가능). 사용량은 **프로젝트 소유 계정**의 `account_assets`에 쌓이고 같은 에셋은 한 번만 셉니다. 초과 시 `413 {error:'storage_limit', limitBytes, usedBytes}`.
- **제안 페이지 표시**: `/api/projects/:id/access` 가 소유자 요금제의 `branding` 을 돌려주고, 무료면 제안 페이지 맨 아래에 "간판다로 만든 제안 · 간판집이라면 무료로 시작하세요"(`proposal-branding`, ganpanda.co.kr 링크).

## 구현 방식
- 좌석: 계정마다 Durable Object `Account`가 좌석을 셉니다. 방 소켓이 열릴 때 역할이 viewer 가 아니면 좌석을 받고(`x-owner` 헤더), 닫히면 반납, 90초 이상 갱신이 없으면 자동 반납 → [../server/internals.md](../server/internals.md).
- 사용량: `GET /api/me` 의 `usage {storageBytes, seats, proposals}` · `limits {storageBytes, seats, proposalsPerMonth}`(null = 무제한). 설정 "계정 · 구독"과 계정 메뉴에 표시(`usage-storage`, `usage-seats`, `usage-proposals`).
- 테스트: `server/test/limits.test.ts`, `tests/e2e/limits.spec.ts`, `tests/e2e/proposal.spec.ts`(월 한도·브랜딩).

## 요청판 (계획, 2026-10-17 결정)
가게 사장의 견적 요청을 가입 간판사에게 전달하고, 간판사가 제안 링크로 답하는 판 → [decisions.md](decisions.md).
- **간판사 과금 = 제안 보낼 때 건당 선불**(또는 건수가 포함된 구독). 성사 수수료 없음 — 성사는 확인할 수 없어 새고, 제안 발송은 간판다가 쥐고 있음. **요청판 제안도 위 요금제의 제안 건수 그대로** — 무료는 월 3건 안에서, 베이직·프로는 무제한. 별도 단가 없음 (2026-10-17 사용자: "요금제는 그대로").
- **홍보자 수수료** = 자기 코드로 들어온 요청에 간판사 제안이 와서 요금이 발생한 만큼의 일부(비율 미정). 간판다가 받은 돈 안에서만 지급, 지급은 계좌이체(기록만 간판다에).
- **가게 사장 무료**, 돈은 고객↔간판사 직접(책임 원칙).
- 허위 요청 방지: 전화 인증, 사진 필수, 번호당 건수 제한, 간판사 신고 → 환불·홍보자 차감.
- 시작은 가입 간판사가 있는 **한 지역**, 홍보자도 그 지역만.

## 대체된 표 (2026-10-13 → 2026-10-17 대체됨)
무료 50MB·3명 / 스타터 2GB·5명·월 5만 원 / 프로 10GB·10명·월 10만 원. 좌석에 초대 고객도 포함했었음. 바꾼 이유: 간판집은 GB 로 생각하지 않고 가치 단위는 제안·수주 건수이며, 고객이 링크를 열다 "인원 초과"를 만나면 확산이 막히기 때문 → [decisions.md](decisions.md).
