# 요금제

## 요약
기본은 무료입니다. 무료와 유료는 **한 달 제안 링크 건수**와 **제안 페이지의 간판다 표시**로 나뉘고, 유료끼리는 **멤버 수**와 저장 용량으로 나뉩니다(2026-10-21 — 전엔 동시 작업 인원).
**고객(viewer 초대) 열람은 어떤 요금제에서도 인원에 세지 않습니다** — 제안 링크가 퍼지는 길을 막지 않기 위해서입니다. (2026-10-17 개편, 이전 표는 아래 "대체된 표")

## 상태
구현됨 — 한도·안내만. 결제는 미구현이며 `accounts.plan` 은 관리자가 바꿉니다(`free` / `basic` / `pro`, 옛 `starter` 는 베이직으로 읽음). 기준표 `server/src/plans.ts`.

## 요금제

| 요금제 | 월 요금 | 제안 링크 | 멤버 (소유자 제외) | 저장 용량 | 제안 페이지 | 버전 되돌리기 |
|---|---|---|---|---|---|---|
| 무료 `free` | 0원 | 한 달 3건 | 2명 | 100MB | "간판다로 만든 제안" 표시 | 없음 |
| 베이직 `basic` | 30,000원 | 무제한 | 5명 | 5GB | 표시 없음 | 최근 7일 |
| 프로 `pro` | 60,000원 | 무제한 | 10명 | 20GB | 표시 없음 | 최근 30일 + 직접 저장 계속 |

2026-10-21 사용자: "무료사용 100mb로 변경해줘 그리고 동시접속은 2인으로 … 다른 요금제도 동시 접소인원 1.5배로 그리고 동시접속이라고 했는데 맴버가입수이다." → 무료 용량 500MB → 100MB, 한도를 동시 작업 인원에서 **멤버 수**로(무료 2명). 동시 접속은 막지 않는다. 이어서 "베이직 5명 프로 10명" → 베이직 5명, 프로 10명(처음의 1.5배 3·8명을 대체).

금액은 부가세 포함 여부 미정. 유료 기능으로 계획 중: 팀 라이브러리, 공급사 발주 연동(프로).

## 원칙 (2026-10-17)
- **결제·계약금 수납·에스크로는 플랫폼에서 하지 않습니다.** 돈이 간판다를 거치면 시공 분쟁·환불·하자 책임이 간판다로 옵니다. 돈은 간판집 계좌로 직접, 간판다는 합의(승인 스냅샷)와 사양을 기록·전달만 합니다 → [decisions.md](decisions.md).
- 검토 중인 수익원: 구독(직원 좌석만), 문서 건당 과금(계약 확인서·주문서·허가 도면), 공급사 발주 수수료(B2B 전달).

## 규칙
- **제안 링크**: [제안 보내기]로 만든 viewer 링크(`invites.kind = 'proposal'`)만 셉니다. 보통 초대 링크(보기·편집)는 세지 않습니다. 계정의 **모든 프로젝트 합산**, 달은 UTC 1일 기준(`monthStart`). 한도에 닿으면 `402 {error:'proposal_limit', used, limit}` 이고 앱은 "무료 요금제는 제안 링크가 한 달 3건까지…"로 안내합니다(`proposal-error`).
- **멤버 수**(2026-10-21): 설정 "멤버"에서 소유자가 이메일로 추가한 팀 멤버(`team_members`) 수, 소유자 제외. 한도에 닿으면 `403 {error:'member_limit', used, limit}`, 앱은 "지금 요금제는 멤버를 N명까지…"(`member-error`). 이미 있는 멤버를 다시 보내는 것(정산 보기 바꾸기)은 세지 않는다. **동시 접속 제한은 없다**(옛 좌석·`429 seat_limit`·`seat-limit` 배너는 없앰).
- **같은 아이디 동시 사용**(2026-10-21 사용자: "동시에 같은 아이디로 작동시 로그아웃 선택하도록 동시에 사용하지 않으면 로그인 유지"): 로그인한 앱은 화면이 보이는 동안 30초마다(다시 보일 때도) 기기 ID(`ganpanda.device`)로 사용 중 신호(`POST /api/me/presence`)를 보낸다. **기기 2대까지는 함께 쓴다**(2026-10-21 "아이디 같이 사용되는거 2개까지는 허용", 서버 `DEVICES_ALLOWED` → 응답 `allowed`). 3대째가 지금(70초 안) 쓰고 있으면 모든 기기 위에 떠 있는 안내(`session-conflict`) — **[다른 곳 로그아웃]**(`POST /api/me/logout-others`: 이 세션 말고 그 계정의 세션을 모두 끊음 → 다른 기기는 다음 신호에서 401 이라 "다른 곳에서 로그아웃을 선택해 여기서는 로그아웃되었습니다" 안내와 함께 로그아웃) / **[여기서 로그아웃]**. 같은 기기의 탭 여러 개는 동시 사용이 아니다. 동시에 쓰지 않으면 아무 일 없이 로그인 유지.
- **저장 용량**: 에셋 업로드·다운로드는 `?project=<id>` + 자격(세션 또는 초대)이 필요합니다(viewer 도 대화 첨부를 위해 업로드 가능). 사용량은 **프로젝트 소유 계정**의 `account_assets`에 쌓이고 같은 에셋은 한 번만 셉니다. 초과 시 `413 {error:'storage_limit', limitBytes, usedBytes}`.
- **제안 페이지 표시**: `/api/projects/:id/access` 가 소유자 요금제의 `branding` 을 돌려주고, 무료면 제안 페이지 맨 아래에 "간판다로 만든 제안 · 간판집이라면 무료로 시작하세요"(`proposal-branding`, ganpanda.co.kr 링크).

## 구독 정지 (2026-10-21, 결제 미구현 — 결제를 붙일 때 이대로)
사용자: "구독이 정지시 정책은?" → "7일은 다음 구독에 합산되나?" → "그렇게 정하고 결정 기록에 남겨줘".
- **결제 실패 → 7일 유예**: 모든 기능을 그대로 쓰고, 소유자 화면에 결제 안내.
- **유예는 다음 구독에 합산하지 않는다**: 유예 중에 결제하면 **다음 결제일은 원래 날짜 그대로**(유예로 쓴 날은 이번 구독 기간 안). 매달 결제를 늦춰 기간을 늘리는 쓰임을 막는다.
- **7일 안에 결제가 없으면 무료로 전환**, 그 7일은 청구하지 않는다. 데이터(프로젝트·사진·사인물·대화)는 지우지 않고, 고객에게 보낸 제안 링크도 계속 열린다. 무료 한도를 넘은 저장 용량은 새 업로드만 막는다(지금 코드 동작과 같음).
- **다시 구독하면 그날이 새 결제일**, 즉시 복원.
- **간판다 쪽 장애로 못 쓴 기간**은 유예와 별개의 보상으로 다음 구독에 더해 준다(보상 정책은 따로 정함).
- 미정: 무료 한도(2명)를 넘는 멤버를 보기 전용으로 바꿀지(지금은 계속 편집 가능 — 새로 추가만 막음), 오래 결제하지 않은 계정의 데이터를 정리할지(권장: 자동 삭제 없음).

## 구현 방식
- 같은 아이디 동시 사용: 계정마다 Durable Object `Account`의 `presence(device, session, updated_at)` — `beat`·`dropOthers`·`leave`, 70초(`PRESENCE_TTL`) 넘은 신호는 쓰지 않는 기기 → [../server/internals.md](../server/internals.md). (옛 좌석 `seats` 표는 남아 있지만 쓰지 않는다.)
- 사용량: `GET /api/me` 의 `usage {storageBytes, members, proposals}` · `limits {storageBytes, members, proposalsPerMonth}`(null = 무제한). 설정 "계정 · 구독"과 계정 메뉴에 표시(`usage-storage`, `usage-members`, `usage-proposals`).
- 테스트: `server/test/limits.test.ts`, `tests/e2e/limits.spec.ts`, `tests/e2e/proposal.spec.ts`(월 한도·브랜딩).

## 요청판 (계획, 2026-10-17 결정)
가게 사장의 견적 요청을 가입 간판사에게 전달하고, 간판사가 제안 링크로 답하는 판 → [decisions.md](decisions.md).
- **간판사 과금 = 제안 보낼 때 건당 선불**(또는 건수가 포함된 구독). 성사 수수료 없음 — 성사는 확인할 수 없어 새고, 제안 발송은 간판다가 쥐고 있음. **요청판 제안도 위 요금제의 제안 건수 그대로** — 무료는 월 3건 안에서, 베이직·프로는 무제한. 별도 단가 없음 (2026-10-17 사용자: "요금제는 그대로").
- **홍보자 수수료** = 자기 코드로 들어온 요청에 간판사 제안이 와서 요금이 발생한 만큼의 일부(비율 미정). 간판다가 받은 돈 안에서만 지급, 지급은 계좌이체(기록만 간판다에).
- **가게 사장 무료**, 돈은 고객↔간판사 직접(책임 원칙).
- 허위 요청 방지: 전화 인증, 사진 필수, 번호당 건수 제한, 간판사 신고 → 환불·홍보자 차감.
- 시작은 가입 간판사가 있는 **한 지역**, 홍보자도 그 지역만.

## 대체된 표 (2026-10-13 → 2026-10-17 대체됨)
무료 50MB·3명 / 스타터 2GB·5명·월 5만 원 / 프로 10GB·10명·월 10만 원. 좌석에 초대 고객도 포함했었음. 바꾼 이유: 간판집은 GB 로 생각하지 않고 가치 단위는 제안·수주 건수이며, 고객이 링크를 열다 "인원 초과"를 만나면 확산이 막히기 때문 → [decisions.md](decisions.md).

## 체험 전환·사업자 확인 (계획, 2026-10-21 결정 — 결제 연동과 함께 구현)
사용자: "무료를 제거하고 14일 무료 사용후 전환" → 조건 합의 → [decisions.md](decisions.md). 구현 전까지는 위 무료 요금제가 그대로 동작한다.
- **요금제**: `trial`(시작일) → `basic` / `pro` → 미전환·미결제는 `archived`(보관). 무료 `free` 는 없앤다.
- **체험**: 로그인만으로 즉시 시작(카드 없음), **사업자 1개당 1회**(사업자 확인 전에는 카카오 계정당 1회), 14일 + "7일 더" 셀프 연장 1회. 체험 중 제안 페이지에는 "간판다로 만든 제안" 표시(지금 무료와 같음).
- **보관(읽기 전용)**: 프로젝트·사진·대화는 보이고 편집·업로드·제안 보내기만 막는다. **이미 보낸 제안 링크는 계속 열린다.** 구독 정지 7일 유예 뒤 "무료로 전환"은 "보관으로 전환"이 된다. 다시 구독하면 즉시 복원.
- **사업자 확인 — 구현됨(2026-10-21)**(소유자 계정, 설정 "계정"): 사업자등록번호·대표자명·개업일 → 국세청 공공데이터 API(상태조회·진위확인, 키는 secret) → `business {번호, 상호, 상태, 확인일}` → [../features/accounts.md](../features/accounts.md#사업자-확인-2026-10-21-serversrcbusinessts--srclibbusinessts--corebusinessts). 불일치면 사업자등록증 사진 → 운영자 승인. 폐업은 월 1회 재조회 — 폐업이면 새 제안 보내기를 막고 안내(데이터 보관). 유료 전환(세금계산서)·제안 페이지 배지·요청판 자격의 조건. 업종은 API 가 안 주므로 가리지 않는다.
- 순서: 카카오 로그인(운영 키 등록) → 사업자 확인 → 체험 전환 → 결제.
