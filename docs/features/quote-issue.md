# 견적 발행 · 박제 · 변경 견적 · 고객 안전장치 (2026-10-26)

사용자:
- "견적의 원가 배수도 바로바로 수정 가능해야하는데 중요한건 해당일 이후부터 적용되어야한다. 견적이 발행되면 관계데이터가 아니라 박제되어야 하는 부분이 있다."
- "항상 확인이 필요한건 전체 적용된다는 표시를 하고 임시 가격이 필요한 경우 원 가격은 따로 표시"
- "원가는 전체 변경이다. 항상 대화창으로 확인. 박제라는 건 견적을 발행하고 다시 호출할땐 그간 원가 견적 금액이 변경되어도 이전에 발행 상태로 나와야한다는 것이다. 만약 견적을 변경한다면 다시 발행하고 고객과 협의를 해야하고 고객이 거절하면 계약 견적으로 진행해야한다. 고객이 간판업체의 견적을 선택한 경우 해당 견적을 기준으로 이후 변경 견적의 차이를 쉽게 확인하는 시스템을 준비해야한다. 새로운 제안과 변경이 고객에게 손해가 나거나 변경을 이해하지 못하게 복잡한 변경을 시스탬적으로 잡아내서 고객에게 안전장치를 해주어야한다."

## 상태: 구현됨

## 발행 = 박제
- **발행 시점 = 제안 링크 발급**(`ProposalDialog` → `app.issueQuote`). 그 순간의 사인물 사양(`snapshotOf`)·견적 줄(수량·단위·단가·원가·금액)·합계를 **값 그대로** 프로젝트 문서 `settings.issues`(최신이 뒤, 최대 50)에 남긴다 — 단가표·원가·배수를 다시 계산하지 않는다(`core/quoteChange.ts issueOf`). 내용이 마지막 발행본과 같으면 새로 만들지 않는다. 번호 #1, #2 …
- **고객에게는 발행본만** 보인다(`ProposalView` — 사인물 목록·치수·금액·자세한 금액·사진 위 외곽선도 발행본의 사인물만). 사장이 발행 뒤 고친 내용은 **다시 발행해야** 고객에게 간다. 발행본이 없는 옛 제안은 지금 내용 그대로.
- **사장 화면**: 리스트 뷰 견적 칸 위 `issue-banner` — "발행 #n · 합계 · 계약 #m", 고쳤으면 "발행 뒤 바뀜 — 고객에게는 발행 #n이 보입니다" + [바뀐 내용](계약 견적, 없으면 마지막 발행본과 비교) + [변경 견적 발행]. 제안 창에도 "고객에게 이렇게 보입니다"(`proposal-change-preview`)와 [변경 견적 발행 (#n)].
- **다시 열어도 발행 상태**: 발행한 프로젝트는 전체 원가 배수가 바뀌어도 발행 당시 단가표 그대로 계산한다. "원가 배수가 바뀌었습니다 — 이 견적은 발행 당시 원가 그대로" + [현재 원가로 다시 계산](확인 창) → 금액이 바뀌면 "발행 뒤 바뀜" → 변경 견적으로 다시 발행.

## 계약 견적 · 변경 견적
- **계약 견적** = 고객이 [진행 동의]한 발행본(`approvals[].proposalId` = 발행본 id). 서버는 고객이 보낸 사본 대신 **문서에 박제된 발행본의 해시·사본**으로 기록한다(`room.ts addApproval` — 금액을 바꿔 보낼 수 없다). 메시지 "견적 #n에 진행에 동의".
- 계약 뒤 새로 발행하면 고객 화면은 **변경 견적 #n** — 계약 견적과의 차이(`QuoteChange.svelte`: 합계 전후·증감, 사인물별 추가·빠짐·변경 필드 전→후)와 안전장치를 보고 **[변경에 동의]**(새 계약) 또는 **[거절 — 계약대로 진행]**. 거절은 `decision: 'rejected'` 기록·"변경 견적 #n을 거절했습니다 — 계약 견적대로 진행" 메시지, 프로젝트 상태·요청 승인은 그대로, 고객 화면은 계약 견적을 보인다(`core/quoteChange.ts customerView`). 거절 기록은 동의로 세지 않는다(`approvalState`).

## 고객 안전장치 (`customerRisks`)
| 코드 | 수준 | 잡는 것 |
|---|---|---|
| `price-up-same-spec` | 위험 | 사양(크기·종류·시트·옵션·문구·디자인)은 그대로인데 금액 인상 |
| `smaller-not-cheaper` | 위험 | 크기가 작아졌는데 금액이 줄지 않음 |
| `less-not-cheaper` | 위험 | 옵션이 빠졌는데 금액이 줄지 않음 |
| `unit-up` | 경고 | 같은 단가 항목의 단가 인상 |
| `total-up` | 경고 | 합계 인상 |
| `complex` | 경고 | 사인물 4개 이상이 한 번에, 또는 한 사인물에 3가지 이상 바뀜 — 하나씩 확인 |
| `removed` | 알림 | 항목이 빠짐 |
고객에게 이로운 변경(더 크고 같은 금액, 금액 인하)은 잡지 않는다. 사장은 발행 전에 같은 경고를 미리 본다.

## 원가 배수 = 전체 적용
- 원가 배수(전체·분류·직접 출력)는 **소유자 계정의 전체 설정**. 프로젝트 접근 정보(`/api/projects/:id/access` `costMarkup`, 소유자·팀에게만)로 내려와 **발행 전 견적**의 연결 항목(공급 원가 × 배수)에 바로 쓰인다. 발행한 견적은 위처럼 그대로.
- 바꾸는 곳: **단가 설정 [자재 원가] 탭에서만**. 리스트 뷰 견적 합계 칸의 원가 배수 ×[ ]는 **뺐다**(2026-10-26 "공급가 합계의 원가배수는 제거해줘 여기에서 한번에 변경하면 안된다" — 견적을 보다가 전체 원가를 한 번에 바꾸지 않게). **바꿀 때마다 확인 창** "전체 적용 — 내 모든 견적(아직 발행하지 않은 것)과 새 견적에 바로 적용, 이미 발행한 견적은 그대로", 취소하면 입력이 되돌아간다. 팀 멤버는 바꿀 수 없다(회사 대표 계정).
- **견적 줄 원가 수정**(2026-10-26 "견적 아이템 아래의 내용은 현재 길이를 제거한다. 그리고 아이템라벨을 클리기하면 원가수정 버튼나오게 하고 수정후 적용(이후 모든 견적에 적용됩니다.)"): 줄 아래 늘 보이던 단가 줄([수량 × 단가 · 이 줄만 · 이 견적 전체 · 내 단가표까지], 2026-10-24)은 **뺐다**. 항목 이름(`line-open`)을 누르면 **[원가 수정]**(`line-cost-edit`) → 수량 × [단가](`line-cost-editor`) · **[적용]** = 확인 창 "이후 모든 견적에 적용됩니다 — 내 단가표 + 이 견적의 같은 품목, 발행한 견적은 그대로" · [이 줄만](임시) · [취소]. [이 견적 전체]만 따로 하는 단추는 없앰. **고른 줄은 카드로 띄운다**(2026-10-26 "선택되서 편집 가능한 상태를 다른 엘리먼트와 차별화(아웃라인으로 감싸거나 그림자로 살짝 띄우기)"): 이름을 누른 줄 · 원가 수정 칸 · 구성품 표를 한 덩어리(`quote-line-block`, `data-selected`)로 강조색 테두리 + 그림자, 원가를 고치는 동안 다른 줄은 흐리게.
- **임시 가격**(이 줄만 단가)은 옆에 **원래 가격**(`line-unit-original`, 단가표 단가)을 따로 보인다.

## 남은 일
- 발행본의 사진 위 외곽선은 지금 위치(사양·금액만 박제). 발행 이력 목록 보기(#1·#2… 열람), 견적서 PDF 출력도 발행으로 볼지.
- 미래 날짜 적용(예: 11월 1일부터 인상)은 아직 없음 — 지금은 확인한 순간부터.
