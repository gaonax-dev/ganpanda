# 사양 글 사전 — 묻고 배우는 퀵입력 (2026-10-18 설계)

사용자(2026-10-18): "메모로 전환하는 글만 모아서 ai로 전환하는 방식으로" → "사용자가 입력한 내용 중에 메모로 전환된 걸 우선 확인하고 답변을 받는다. 다른 사용자가 해당 결정에 문제를 제기하면 이전 설정 사용자에게만 적용한다. 그리고 문제를 제기한 사용자의 설정을 다시 적용하지만 우선순위에 대한 구조를 구성해 전국·지역 그리고 개인의 영역으로".

상태: **설계 결정, 구현은 단계별**(아래 6절). 바탕이 되는 표본 수집은 구현됨([order.md](order.md) 사양 글).

## 1. 흐름
1. 퀵입력(사양 글) 확인 창은 알아본 항목을 체크 목록으로 보여 준다(지금과 같음).
2. **못 알아본 부분이 있으면 먼저 묻는다**: "'로고는 왼쪽 아래'는 무엇인가요?" 답은 확인 창 안에서 고른다.
   - **설정으로** — 레지스트리에서 고른 뜻: 종류·색·채널·LED·옵션 값·배치 명령(왼쪽/가운데/아래, N줄, 시트 위) 중 하나 또는 여럿
   - **요청사항(메모)으로** — 지금처럼 메모에 붙인다
   - **무시** — 아무것도 하지 않는다
3. 답은 **규칙**으로 저장되어 다음부터 그 사용자의 퀵입력이 바로 알아본다. 글 자체는 저장하지 않는다(원칙 유지). 답하지 않은 글은 표본(`spec_samples`)으로만 남아 개발 때 기본 사전을 넓히는 데 쓴다.

## 2. 규칙과 범위(우선순위) — 2026-10-18 보완: "지역 설정이 무한 루프가 될 수 있다. 개인화도 중요해, 지역 사람이 다른 지역에 있을 수도 있어"
```
SpecRule { id, phrase, meaning: SpecItem[] | LayerFragment, scope: 'personal' | 'national', authorId, authorRegion?, createdAt }  // 뜻별 계정 수 집계는 따로 (spec_rule_votes)
```
- 범위는 **개인과 전국 둘**. 해석 순서: **개인 > 전국 > 기본 사전(코드의 별칭 표)**. 개인이 있으면 늘 개인이 이긴다.
- **지역은 강제 범위가 아니라 추천 힌트**: 계정에 붙는 속성(말버릇의 출신, 프로젝트·현재 위치와 무관). 뜻을 고를 때 "같은 지역 사용자들은 이렇게 씁니다"로 먼저 보여 주는 정렬 기준으로만 쓴다. 그러면 사람이 다른 지역에서 일해도 자기 사전이 그대로 적용되고, 지역 단위 정의 문제와 루프 표면이 함께 사라진다.
- 개인 규칙은 승격·이의의 영향을 받지 않는다(사람을 따라간다).

## 3. 승격 — 대세가 기본값 (2026-10-18 사용자: "항상 중요한건 대세야 많이 사용하면 그쪽으로 가야해")
- 같은 말에 뜻이 여럿이면 **독립 계정 수가 가장 많은 뜻**이 전국 기본값(새 사용자·개인 규칙 없는 사용자에게 적용). 나머지 뜻은 그렇게 정한 사람들의 개인 규칙으로만 남는다.
- 전국 기본값이 되려면 최소 **5곳**. 처음에는 운영자가 확인하고 켠다(승인 화면 또는 `npm run rules`); 데이터가 쌓이면 자동.
- 승격은 계정 수로만 일어난다. 작성자가 올리거나 내릴 수 없다.

## 4. 이의 — 한 표, 되돌릴 수 없는 상태 없음
- 전국 기본값으로 알아본 항목이 자기 뜻과 다르면 확인 창에서 **"다른 뜻이에요"** → 자기 뜻을 고른다. 결과는 두 가지뿐: 그 사용자에게 **개인 규칙**이 생기고(그에게는 이것이 이긴다), 그 뜻의 **계정 수가 하나 는다**.
- 다른 뜻이 **다수가 되면 기본값이 그쪽으로 바뀐다**. 기존 뜻으로 정했던 사람들은 자기 개인 규칙 그대로(= "이전 설정 사용자에게만 적용"). 잠금·숨김 같은 되돌릴 수 없는 상태는 두지 않는다 — 대세가 바뀌면 기본값도 따라간다.
- **루프 방지는 문턱으로**: 기본값이 바뀌려면 새 다수가 기존보다 **계정 3곳 이상** 앞서야 하고, 바뀐 뒤 **30일**은 다시 바뀌지 않는다. 근소한 차이로 흔들리지 않되 대세는 따른다.

## 5. 데이터·동작
- 서버 D1 `spec_rules`(id, phrase, meaning JSON, scope, account_id, author_region, created_at) + 뜻별 독립 계정 수 집계(`spec_rule_votes`: phrase, meaning hash, account_id — 한 계정은 한 말에 한 표) + 전국 기본값(`spec_defaults`: phrase, meaning, since). 클라이언트는 로그인 때 자기에게 적용되는 규칙(개인 + 전국)을 내려받아 캐시하고, 파서에 넘긴다: `parseSpecText(text, obj, library, rules)`.
- 파서는 규칙을 **기본 사전보다 먼저**, 긴 말부터 맞춘다. 규칙의 뜻이 `SpecItem[]` 이면 지금 확인 창 항목으로, 레이어 조각이면 2단계 이후 레이어 트리로 들어간다([../architecture/composition-layers.md](../architecture/composition-layers.md)).
- 표본(`spec_samples`)은 답하지 않은 글의 말뭉치로 계속 모은다(사용자가 "보내기"를 켠 것만).

## 6. 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| S0 | 못 알아본 글 표본 수집(보내기 체크, `/api/spec-samples`, `npm run samples`) | 구현됨 (2026-10-18) |
| V1 | **개인 사전**: 확인 창에서 뜻 묻기 → 규칙 저장(`/api/me/spec-rules`) → 파서에 주입 | 다음 |
| V2 | **전국 기본값 = 다수 뜻**(계정 수 집계, 운영자 확인) + **이의**(개인 규칙 + 그 뜻에 한 표; 다수가 바뀌면 기본값도 — 문턱 3곳·30일) | 계획 |
| V3 | **지역 힌트**(계정 지역 필드, 뜻 고를 때 같은 지역 제안 먼저) | 계획 |
| V4 | 뜻을 레이어 조각(배치·중첩)으로 — 레이어 구조 2단계와 함께 | 계획 |
| V5 | **용어 통일**(2026-10-18 사용자: "이후에는 용어의 통일화가 진행된다"): 레지스트리의 값이 **표준 용어**, 쌓인 규칙은 그 **동의어 사전**. 요약·견적서·주문서·공급사 전달은 표준 용어로 쓰고(사용자 표현은 괄호로 보여 줄 수 있음), 확인 창은 "'오싸이' → 표준 '오사이'"처럼 되돌려 보여 준다. 동의어 통계로 많이 쓰는 말을 표준 후보로 올리고, 표준 용어집을 내보낸다 | 계획 |

## 7. 열린 점
- "지역"의 단위(시·도 / 시·군·구)와 계정에 넣는 방법(가입 때 선택 / 설정). 힌트로만 쓰므로 느슨해도 된다. V3 에서 정한다.
- 팀 그룹 안 공유를 개인과 전국 사이에 둘지(그룹 규칙).

## 8. 용어 통일 (V5 방향)
- **표준 = 레지스트리 값.** 종류·세부 종류·옵션 값·배치 명령의 이름이 표준 용어다. 새 표현은 규칙으로 표준에 붙는 동의어가 되고, 표준 자체를 늘리는 일은 레지스트리(코드) 변경이다.
- **사용자는 자기 말로, 문서는 표준으로.** 입력은 사용자 표현 그대로 받고, 요약·견적서·주문서·공급사 전달·3D 는 표준 용어로 쓴다. 확인 창에서 "'오싸이' → 표준 '오사이'"처럼 매번 되돌려 보여 주면 쓰면서 표준에 익숙해진다.
- **통계로 표준을 고른다.** 같은 뜻의 동의어 중 가장 많이 쓰이는 말이 표준과 다르면 표준 이름 변경 후보로 올린다(운영자 결정, 코드 변경). 지역 힌트가 있으면 지역별 쓰임도 보인다.
- **용어집 내보내기.** 표준 용어와 동의어를 표로 뽑아 공급사·신입 교육·요금제 안내에 쓴다.
