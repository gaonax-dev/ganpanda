# 커뮤니케이션 (대화·코멘트)

## 요약
사인물 오브젝트마다 카톡형 대화와 검토 코멘트를 주고받습니다. 1차 개발의 중심 기능입니다.

## 상태
구현됨 — 오브젝트별 대화·코멘트(기반), 실시간 공유(1-1), 안 읽은 메시지·알림(1-3a), 사진 위치 코멘트(1-3b), 사진·파일 첨부(1-3c), **톡(방별 대화, 2026-10-22)**

## 톡 — 방별 대화 (2026-10-22)
사용자: "말풍선 제거한다. 말풍선 숫자만 사용한다. 툴의 말풍선은 톡으로 변경한다. 톡은 메인화면의 상단에 톡버튼. 톡은 프로젝트에서 대화 대상을 선택하고 대화방 이름을 지정하고 생성한다. 프로젝트에서 톡방 버튼으로 톡방을 선택하고 필요한 내용을 넣으면 같은 방 상대에게 알림이 간다. 톡방이 켜진 상태에서 사인물을 선택하면 대화에 사인물 링크가 생기고 대화에서 해당 링크를 누르면 해당 링크가 화면에 잡힌다. 톡방에서 사인물 또는 사진을 선택하기 위해서는 대화창을 1/3 정도에서 조금 크게 자리잡게하고 프로젝트를 네비게이션하고 선택한다. 기본으로 회사 맴버 톡방이 있다."
- **상단 [톡]**(`talk-open`, 안 읽은 수 `talk-unread`): 프로젝트 화면 상단 오른쪽. 누르면 톡 창(`ui/TalkPanel.svelte`, `talk-panel`) — **데스크톱은 오른쪽 약 38%(최소 340px), 휴대폰은 아래 42%**. 나머지 화면에서 보드를 옮기고 고른다. 톡이 열려 있는 동안 사인물을 골라도 속성창·빠른 막대는 뜨지 않는다.
- **아이디로 연결, 화면은 닉네임**(2026-10-22 사용자: "닉은 사용하는데 아이디로 연결하라는 거지"): 내 아이디 `app.myId` = 계정 id, 로그인하지 않은 손님은 기기 아이디 `g:<uuid>`. 접속자 상태(awareness)·메시지(`authorId`)·방(`memberIds`, `createdById`)이 아이디를 갖는다. 이름이 바뀌어도 방에 남고, 표시 이름은 지금 이름(접속자·보낸 메시지 `app.talkNames`) > 만들 때 이름(`memberNames`). 서버는 메시지 `authorId` 를 로그인했으면 계정 id 로, 아니면 `g:` 형식만 받는다. 대화 상대 후보는 지금 접속한 사람·이 프로젝트에서 대화한 사람·내 팀 멤버(이름으로 직접 추가는 없앰 — 초대 링크로 한 번 들어오면 후보에 나온다).
- **방**: 기본 **회사 멤버** 방(`TEAM_ROOM`, id `team`, 저장하지 않는 고정 방) — 편집 권한(owner·editor, 회사 쪽)만 보고 쓴다. 서버도 viewer 가 `talk:team` 에 쓰면 403. 그 밖의 방은 회사 쪽이 **[+ 새 톡방]**(`talk-new`)에서 이름(`talk-new-name`)과 대화 상대(`talk-member` — 접속자·대화한 사람·내 팀 멤버, 또는 `talk-new-extra` 에 이름 쉼표로)를 골라 만든다. 방은 **만든 사람 + 멤버(닉네임)**만 본다(`core/talk.ts` `visibleRooms`). 고객(viewer)은 방을 만들지 않는다(문서 쓰기 권한 없음).
- **저장**: 방 = Yjs `talks` 맵(`TalkRoom {id, name, members, createdBy, createdAt}`), 메시지 = 기존 `messages` 배열에 `objectId: 'talk:<방 id>'` — 안 읽은 수·삭제·첨부·서버 RPC(viewer 는 `/api/rooms/:room/messages`)를 그대로 쓴다. 링크는 메시지의 `refs[{kind: object|photo|pin, id, label}]`(서버 `parseRefs` — 모르는 종류는 버림, 20개까지).
- **링크 붙이기**: 방이 열린 채 ① 사인물을 고르면 🔗(연결본은 원본 id), ② 사진 빈 곳을 **탭**하면 📷, ③ 방 머리의 **📍** 를 켜고 사진을 누르면 번호(숫자만 말풍선)를 찍고 그 번호를 📍#n 으로 — 보낼 링크 칩(`talk-pending-ref`, × 로 빼기). 글 없이 링크만 보내도 된다.
- **링크 글은 지금 이름**(2026-10-22 "링크를 사인물이름으로 … 사진도 사진이름으로"): 🔗 사인물 이름, 📷 사진 이름(사진 설정 [이름 변경]), 📍 #번호 — 이름이 바뀌면 링크 글도 바뀐다(`app.refText`, 지워졌으면 보낼 때 이름).
- **링크 누르기**(`talk-ref`): 사진보드로 가서 그 사인물을 고르고, 사인물·번호를 톡 창에 가리지 않는 쪽 화면 가운데에 크게 맞춘다(`app.focusRef` → `reveal` 에 objectId/pinId). 링크로 고른 사인물은 다시 링크로 붙지 않는다. 지워진 대상이면 안내.
- **알림**: 같은 방 사람에게만 — 보이지 않는 방의 메시지는 토스트·브라우저 알림·안 읽은 수에서 빠진다(`canSeeTalkMessage`, `talkUnread`). 보고 있는 방은 알리지 않고 읽음 처리. 토스트를 누르면 그 방이 열린다. 앱 밖 푸시(앱을 닫았을 때)는 아직 없다.
- **메인 화면 톡**(2026-10-22 "메인화면에서 모든 톡방을 열어서 확인하고 링크를 누르면 해당 프로젝트의 링크로 이동"): 홈의 **톡** 칸(`ui/HomeTalks.svelte`, `home-talk`) = 내가 멤버(계정)인 모든 프로젝트의 방, 최근 대화 순, 안 읽음 "새". 누르면 거기서 읽고(`home-talk-room`) 답한다(`home-talk-input`). 링크(`home-talk-ref`)를 누르면 `/?room=<프로젝트>&talk=<방>&focus=<종류>:<id>` 로 가서 방을 열고 그 대상을 화면에 잡는다(`applyStartTalk` — 문서가 들어올 때까지 최대 약 6초 기다림). [프로젝트에서 열기]는 방만.
  - 서버 **톡 색인** `talk_index`(마이그레이션 0033, 방 멤버 계정마다 한 줄 + 마지막 메시지): 방을 만들거나 톡을 보낸 뒤 앱이 `POST /api/rooms/:id/talk-sync`, viewer·메인에서 보낸 톡은 서버가 바로 다시 만든다(`server/src/talk.ts syncTalkIndex` — Room DO `talkIndex()` 로 문서를 읽음). 회사 멤버 방은 대화가 생기면 소유자 + 팀 멤버에게. 손님 아이디(g:)는 계정이 없어 메인 목록에 없다.
  - **방 멤버는 초대 링크 없이 그 프로젝트에 들어간다**(`resolveAccess`): 팀 멤버 = editor, 그 밖 = viewer. 멤버를 넣는 것 = 초대와 같다.
- [실측] 탭의 💬 안 읽은 수(`unreadTotal`)는 사인물·번호 대화만 센다(톡은 [톡] 단추에).

## 말풍선 = 숫자 (2026-10-22, 아래 2026-10-18 모양은 대체됨)
- 사진·정면도 카드·리스트의 말풍선은 **번호 원만**(`ui/BubbleShape.svelte`): 지점 말풍선은 그 번호(받는 사람이 있으면 옆에 →), 사인물은 대화 수(`app.chatCounts`, 음성·승인 제외). 몸통·요약 글·꼬리·변 끌기·꼭지 손잡이는 없앴다. 원을 끌면 지점이 옮겨지고, 누르면 대화 창. 안 읽은 게 있으면 테두리 강조 + 빨간 작은 수(`{testid}-unread`). testid: `pin`·`object-bubble`·`card-bubble`, 숫자 `…-num`, 누르기 영역 `…-inner`.
- 도구 막대의 **💬 말풍선 단추 제거** — 위치 번호는 톡의 📍 또는 단축키 P(편집·고객 모두).

## 동작
- 오브젝트 패널 아래쪽에 [대화] / [코멘트] 탭이 있습니다. 둘 다 `messages` 배열에 `kind`로 구분해 저장합니다.
- 대화: 내 메시지는 오른쪽 노란 말풍선, 다른 사람은 왼쪽 흰 말풍선 + 이름. 같은 사람이 연속으로 보내면 이름은 한 번만 표시합니다.
- 코멘트: 왼쪽 강조선이 있는 메모 카드입니다.
- Enter로 전송, Shift+Enter로 줄바꿈. 한글 조합 중 Enter는 전송하지 않습니다(`isComposing`).
- viewer(보기·대화만) 역할은 문서를 편집할 수 없으므로 대화를 서버 API로 보내고 서버가 문서에 기록합니다. 화면 동작은 같습니다.
- 표시 이름은 처음 보낼 때 묻고 `localStorage`의 `ganpanda.nickname`에 저장합니다. 상단 오른쪽에서 바꿀 수 있습니다.

## 안 읽은 메시지·알림 (1-3a, `src/lib/core/unread.ts`)
- **안 읽음** = 내가 그 사인물의 대화를 마지막으로 본 시각 이후에 **남이** 보낸 메시지. 본 시각은 기기에 저장(`ganpanda.seen.<room>`, 사인물별). 오브젝트 패널이 열려 있는 동안 그 사인물의 새 메시지는 바로 읽음 처리.
- 표시: 사인물 라벨에 `💬 n`(`sign-unread`), 상단 "사진 보드" 탭에 합계(`unread-total`).
- **토스트**: 앱 시작 이후 도착한 남의 메시지 중, 그 대화를 보고 있지 않거나 탭이 숨겨져 있으면 오른쪽 아래에 8초간 표시(최대 4개). 누르면 그 사인물의 대화가 열립니다.
- **브라우저 알림**: 탭이 숨겨져 있고 권한이 있을 때만. 권한은 사용자가 처음 대화를 보낼 때 요청합니다(브라우저가 사용자 동작을 요구).
- 같은 사람 판정은 표시 이름 비교(아래 한계 참고).

## 말풍선 — 게시물·영역을 지정해 소통하는 창구 (1-3b, 옛 이름 핀)

- **소유주와 완료**(2026-10-18 사용자: "말풍선은 작성자가 소유주이다. 완료를 누르면 컨펌 리스트로 속성에 남기고 화면에서는 말풍선을 제거한다"): 완료·삭제는 **작성자**(이름이 같은 사람) 또는 프로젝트 **소유자**만(`PinPanel` `owns`; 다른 편집자에게는 안내만). [완료](`pin-resolve`, `resolved: true`)하면 사진·카드에서 말풍선이 **사라지고**, 꼭지가 가리키던 사인물의 속성 패널 **✓ 컨펌 리스트**(`object-confirms`·`object-confirm-item`: 번호·작성자·날짜·마지막 글)에 남는다. 사인물을 가리키지 않는 완료 말풍선은 사진 머리의 **[✓ 완료 n]**(`photo-confirms` → `confirm-list`·`confirm-item`)에서. 항목을 누르면 말풍선 창이 열리고 [다시 열기]로 화면에 되돌릴 수 있다. 고객(viewer)이 만든 말풍선은 문서 쓰기 권한이 없어 소유자가 대신 완료한다.
- **꼭지 → 사인물 추적**(2026-10-18 "꼭지점 위치의 사인물을 최대한 추적해 사인물도 같이 선택할 수 있게"): `core/bubbleTarget.ts` `objectAtPoint`(같은 사진에서 꼭지가 외곽선 안인 사인물, 겹치면 작은 것). 말풍선 창에 **[📐 이름 속성]**(`pin-goto-object`) → 그 사인물 선택, 사인물 패널에 **[💬 #n]**(`object-goto-bubble`, 이 사인물을 가리키는 말풍선마다) → 그 말풍선 선택.
- **받는 사람**(2026-10-17 사용자: "툴바에서 핀을 말 풍선으로 변경하고 해당 말 풍선은 받는 사람이 있다. 모두가 보게 할 수도 있다"): 도구 막대 `💬 말풍선`(단축키 P 그대로, testid `tool-pin`). 말풍선 패널의 **받는 사람**(`pin-to`: 모두 / 참여자 — 접속한 사람·대화·말풍선에 등장한 사람, `app.participants`)을 고르면 `Pin.to` 에 이름이 저장되고, **보낸 사람·받는 사람·소유자만** 그 말풍선과 그 대화 알림을 본다(`core/pins.ts` `pinVisibleTo`, `app.visiblePins`). 비우면(기본) 모두. 사진 위 모양은 말풍선(둥근 상자 + 꼬리), 받는 사람이 있으면 번호 뒤에 → 와 `data-to`. 고객(viewer)이 만든 말풍선은 모두에게(서버 API 로 만들며 받는 사람 지정은 편집 권한만).
- 말풍선 = 사진의 한 지점(원본 px)에 꽂는 대화 스레드. 사인물이 아닌 곳("여기에도 간판 하나요")에도 쓸 수 있습니다. 데이터는 `pins`(→ [../architecture/data-model.md](../architecture/data-model.md)), 대화는 `messages`에 `objectId = 핀 id`로 저장하므로 안 읽음 배지·토스트가 그대로 동작합니다.
- 만들기: 핀 도구(P 또는 📍 버튼) → 사진 클릭. **viewer(고객)도 가능** — 문서 편집 권한이 없으므로 `POST /api/rooms/:id/pins`로 서버가 기록합니다.
- 핀 패널: `#번호`, 작성자·시각·사진 이름, 대화. 편집 권한은 **해결로 표시**(핀이 흐려짐, 다시 열기 가능)·**삭제**(대화도 함께)·드래그 이동.
- 번호는 사진 안에서 만든 순서(표시용). 두 사람이 동시에 만들면 같은 번호가 나올 수 있습니다.
- 사진을 지우면 그 사진의 핀과 대화도 지워집니다.

## 사진·파일 첨부 (1-3c)
- 📎 버튼(또는 입력칸에 붙여넣기)으로 **사진·PDF**를 최대 5개(`ATTACH_MAX`) 첨부합니다. 첨부만 있고 글이 없어도 보낼 수 있습니다.
- 파일은 보내기 전에 에셋 API로 올라가며(`putAsset`), **viewer도 올릴 수 있습니다** — 초대한 소유자의 저장 용량에 합산됩니다(2026-10-13 결정). 용량 한도를 넘으면 첨부 칩 자리에 안내가 뜹니다.
- 메시지에는 `attachments[{assetId, name, type, size}]`로 저장됩니다. 말풍선에서 이미지는 썸네일(누르면 새 탭에서 원본), PDF는 이름·크기 링크(`AttachmentView.svelte`).
- 토스트·알림에서 글이 없으면 "사진 2장 · 파일 1개"처럼 요약합니다(`core/attachments.ts`).
