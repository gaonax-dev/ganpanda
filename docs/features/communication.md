# 커뮤니케이션 (대화·코멘트)

## 요약
사인물 오브젝트마다 카톡형 대화와 검토 코멘트를 주고받습니다. 1차 개발의 중심 기능입니다.

## 상태
구현됨 — 오브젝트별 대화·코멘트(기반), 실시간 공유(1-1), 안 읽은 메시지·알림(1-3a), 사진 위치 코멘트(1-3b), 사진·파일 첨부(1-3c)

## 동작
- 오브젝트 패널 아래쪽에 [대화] / [코멘트] 탭이 있습니다. 둘 다 `messages` 배열에 `kind`로 구분해 저장합니다.
- 대화: 내 메시지는 오른쪽 노란 말풍선, 다른 사람은 왼쪽 흰 말풍선 + 이름. 같은 사람이 연속으로 보내면 이름은 한 번만 표시합니다.
- 코멘트: 왼쪽 강조선이 있는 메모 카드입니다.
- Enter로 전송, Shift+Enter로 줄바꿈. 한글 조합 중 Enter는 전송하지 않습니다(`isComposing`).
- viewer(보기·대화만) 역할은 문서를 편집할 수 없으므로 대화를 서버 API로 보내고 서버가 문서에 기록합니다. 화면 동작은 같습니다.
- 표시 이름은 처음 보낼 때 묻고 `localStorage`의 `ganpanda.nickname`에 저장합니다. 상단 오른쪽에서 바꿀 수 있습니다.

## 안 읽은 메시지·알림 (1-3a, `src/lib/core/unread.ts`)
- **안 읽음** = 내가 그 사인물의 대화를 마지막으로 본 시각 이후에 **남이** 보낸 메시지. 본 시각은 기기에 저장(`ganpanda.seen.<room>`, 사인물별). 오브젝트 패널이 열려 있는 동안 그 사인물의 새 메시지는 바로 읽음 처리.
- 표시: 사인물 라벨에 `💬 n`(`sign-unread`), 상단 "사진 보드" 탭에 합계(`unread-total`).
- **토스트**: 앱 시작 이후 도착한 남의 메시지 중, 그 대화를 보고 있지 않거나 탭이 숨겨져 있으면 오른쪽 아래에 8초간 표시(최대 4개). 누르면 그 사인물의 대화가 열립니다.
- **브라우저 알림**: 탭이 숨겨져 있고 권한이 있을 때만. 권한은 사용자가 처음 대화를 보낼 때 요청합니다(브라우저가 사용자 동작을 요구).
- 같은 사람 판정은 표시 이름 비교(아래 한계 참고).

## 말풍선 — 게시물·영역을 지정해 소통하는 창구 (1-3b, 옛 이름 핀)
2026-10-17 사용자: "말풍선이 해당 게시물 또는 영역을 지정해서 소통하는 창구다. 실제로는 현재 속성에 있는 대화 코멘트를 대체한다고 보면 된다. 말풍선에는 마지막 상태만 나오게" → 방향: **대화는 모두 말풍선으로 모인다** — 지점 말풍선(사진의 한 점), 사인물 말풍선(영역에 붙음, 대화 id = 사인물 id). 속성 패널의 대화 섹션은 **2026-10-18 제거**(사용자: "속성 패널에서 대화 섹션 빼줘") — 사인물 대화는 **말풍선 창**(`ui/ObjectChatPanel.svelte`, `object-chat`)에서만: 사진 위 사인물 말풍선을 누르거나, 속성 패널 머리의 💬(`object-chat-open`, 안 읽은 수 배지) 또는 휴대폰 빠른 막대의 💬(`quick-chat-open`)로 연다(`app.openChat(id)`, `app.chatObjectId`). 창이 열린 동안 속성 패널 자리를 차지하고 ✕(`object-chat-close`)로 닫으면 패널로 돌아간다. 다른 사인물을 고르면 닫힌다. **마지막 상태만**: 보드 위 말풍선 옆에 `✓ 해결됨` 또는 `작성자: 마지막 메시지 요약`(18자, `core/bubbles.ts` `lastStateOf`·`bubbleLabel`)만 보이고, 전체 대화는 눌러서 연다. 사인물 말풍선(`object-bubble`)은 대화가 있는 사인물의 오른쪽 위 꼭짓점에 생기고(안 읽은 수 또는 …), 누르면 그 사인물을 선택하고 대화 패널을 연다(`onchat`). 지점 말풍선의 요약은 `pin-last`. 특허 준비 → [../product/patent-bubble.md](../product/patent-bubble.md).
- **받는 사람**(2026-10-17 사용자: "툴바에서 핀을 말 풍선으로 변경하고 해당 말 풍선은 받는 사람이 있다. 모두가 보게 할 수도 있다"): 도구 막대 `💬 말풍선`(단축키 P 그대로, testid `tool-pin`). 말풍선 패널의 **받는 사람**(`pin-to`: 모두 / 참여자 — 접속한 사람·대화·말풍선에 등장한 사람, `app.participants`)을 고르면 `Pin.to` 에 이름이 저장되고, **보낸 사람·받는 사람·소유자만** 그 말풍선과 그 대화 알림을 본다(`core/pins.ts` `pinVisibleTo`, `app.visiblePins`). 비우면(기본) 모두. 사진 위 모양은 말풍선(둥근 상자 + 꼬리), 받는 사람이 있으면 번호 뒤에 → 와 `data-to`. 고객(viewer)이 만든 말풍선은 모두에게(서버 API 로 만들며 받는 사람 지정은 편집 권한만).
- 말풍선 = 사진의 한 지점(원본 px)에 꽂는 대화 스레드. 사인물이 아닌 곳("여기에도 간판 하나요")에도 쓸 수 있습니다. 데이터는 `pins`(→ [../architecture/data-model.md](../architecture/data-model.md)), 대화는 `messages`에 `objectId = 핀 id`로 저장하므로 안 읽음 배지·토스트가 그대로 동작합니다.
- 만들기: 핀 도구(P 또는 📍 버튼) → 사진 클릭. **viewer(고객)도 가능** — 문서 편집 권한이 없으므로 `POST /api/rooms/:id/pins`로 서버가 기록합니다.
- 핀 패널: `#번호`, 작성자·시각·사진 이름, 대화. 편집 권한은 **해결로 표시**(핀이 흐려짐, 다시 열기 가능)·**삭제**(대화도 함께)·드래그 이동.
- 번호는 사진 안에서 만든 순서(표시용). 두 사람이 동시에 만들면 같은 번호가 나올 수 있습니다.
- 사진을 지우면 그 사진의 핀과 대화도 지워집니다.

## 사진·파일 첨부 (1-3c)
- 📎 버튼(또는 입력칸에 붙여넣기)으로 **사진·PDF**를 최대 5개(`ATTACH_MAX`) 첨부합니다. 첨부만 있고 글이 없어도 보낼 수 있습니다.
- 파일은 보내기 전에 에셋 API로 올라가며(`putAsset`), **viewer도 올릴 수 있습니다** — 초대한 소유자의 저장 용량에 합산됩니다(2026-10-13 결정). 용량 한도를 넘으면 첨부 칩 자리에 안내가 뜹니다.
- 메시지에는 `attachments[{assetId, name, type, size}]`로 저장됩니다. 말풍선에서 이미지는 썸네일(누르면 새 탭에서 원본), PDF는 이름·크기 링크(`AttachmentView.svelte`).
- 토스트·알림에서 글이 없으면 "사진 2장 · 파일 1개"처럼 요약합니다(`core/attachments.ts`).

## 알려진 한계
- "내 메시지" 판단이 이름 비교입니다. 같은 이름을 쓰는 다른 사람도 내 메시지로 보입니다. → 로그인·참여자 ID 도입 시 교체
- 안 읽은 메시지 표시, 알림 없음

## 접속자 표시가 남지 않게 (2026-10-15 사용자: "실시간 변경 잘 연동되는데 사용자가 나가도 표시가 계속 남는다")
- 브라우저(특히 휴대폰)는 탭을 숨기거나 닫을 때 소켓을 바로 닫지 않는 일이 많아, 서버가 "나감"을 몰랐습니다(y-websocket 은 브라우저 종료를 알리지 않음).
- **앱**(`src/lib/sync.ts`): 탭이 숨으면(`visibilitychange` hidden) 내 표시를 지우고 다시 보이면 복원, 페이지를 떠나면(`pagehide`) 표시를 지우고 연결을 끊음, 뒤로가기 복원(`pageshow` persisted)이면 다시 연결.
- **서버**(`Room`): 접속자 상태에 `updated_at` 을 두고, 30초 넘게 갱신 없는 상태(클라이언트는 15초마다 갱신)는 새로 들어온 사람에게 보내지 않고 정리.
- 테스트: `tests/e2e/realtime.spec.ts`(숨김·떠남), `server/test/sync.test.ts`(30초 조용한 상태).
