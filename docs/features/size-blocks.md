# 치수 블록 — 크기를 아는 네모로 원근과 예상 크기의 기준을 잡는다

## 요약
사진 위에 **치수 블록**(네모)을 그리고 가로·세로(입력값)와 축(면)을 넣습니다. 블록은 사진의 것이고 블록마다 치수·방향이 다릅니다. 블록이 있으면 그 사진 사인물들의 **예상 크기는 블록이 기준**이고, 원근도 치수 있는 벽면 블록으로 잡힙니다. 블록에는 입력한 값만 보이고 추정치는 없습니다. 블록은 견적·리스트에 들어가지 않습니다.

사용자 결정 흐름:
- 2026-11-03 "같은 크기 사각형으로 나머지 사인물 대략 크기를 정확도 높게 … 모서리 대각으로 같은크기 블록" → "설정이 하나인 사각이 두개" → "치수블록은 핫핑크라인으로". 길이 블록(사인물 변의 눈금)은 넣지 않음.
- 2026-11-04 "형광색으로 블록을 변경해주고 사인물과 같이 컨트롤로가 있어야" → "x마크는 제거" → "블록은 속성이 사이즈와 축설정만 있다. 항상 바로 보이게" → "블록 치수는 사용자가 입력한 값을 사용하고 추정치는 여기에 없다. 블록은 입력한 값만 나오고 여러 값과 방향을 지원한다. 블록이 있으면 사인물들의 예상 크기는 블록이 기준이 된다".
- **대체됨**: 2026-11-03~04 오전의 "블록 = 사인물에 붙은 같은 크기 사각(치수 공유)", 블록 위 ≈ 추정 글자, ✕ 단추, 핫핑크 선.

## 화면
- **[블록] 도구**(`tool-block`, 하단 도구 막대 [사각] 옆): 늘 켜져 있다(3D 단계 제외). 네모를 끌어 그리면 그 사진의 블록이 되고 바로 선택되어 패널이 열린다. 고른 사인물(같은 사진, 치수 입력)이 있으면 그 치수로 시작, 아니면 비어 있다. 모서리를 이어 가는 작업이라 도구는 유지(Esc 두 번 — 입력 칸에서 나온 뒤 — 또는 [선택]으로 끝).
- **대각 예측**(`predictBlock`): 원근이 있고 시작점이 고른 사인물·벽면 블록의 꼭짓점 가까이(화면 14px)이면, 그 꼭짓점에 모서리를 맞댄 **같은 크기·같은 치수** 블록을 끌어간 방향으로 놓는다.
- **표시**(`size-block[data-id=사진][data-index]`): 선 **형광 초록** `#39ff14`, 가운데에 **입력한 치수만**(`block-size` — "4,000×1,000", 없으면 빨간 "치수 입력"). 지금 원근으로 잰 크기가 입력 치수와 10%(`BLOCK_FIT_TOL`) 안이면 선·글자 **보라**(`data-fit`) — 숫자(추정)는 보이지 않는다. [정보]·[구별선] 토글을 따른다.
- **조작 = 사인물과 같은 손잡이**: 블록을 누르면 블록이 선택되고(`app.selectedBlock`, 사인물 선택과 배타) 조작 손잡이 층(`sign-controls[data-block]`)이 붙는다 — 꼭짓점·변 손잡이, 벽축 면 막대(끝 동그라미 = 축 바꾸기), [원근에 맞추기]. 블록을 **가짜 사인물**(id `<사진 id>#b<번호>`, `blockIdOf`/`parseBlockId`)로 같은 코드에 넣고 BoardView 가 `onselect`/`onquad`/`onbox` 를 블록으로 보낸다. 블록 안을 끌면 통째로 옮김. 지우기는 **Delete 키**(✕ 없음). 모두 ⌘Z.
- **블록 패널**(`ui/BlockPanel.svelte`, `block-panel`): 블록을 고르면 휴대폰·데스크톱 모두 바로. **가로·세로**(`block-width`·`block-height`, 이 블록의 입력값, 비면 형광 테두리)와 **축** 단추 셋(`block-axis-y` 벽면 · `block-axis-x` 옆면 · `block-axis-z` 수평, 정하지 않으면 벽면이 옅게). 그 밖의 것은 없다.

## 판독·원근
- **블록이 기준**(`app.measures`): 사진에 치수 있는 블록이 하나라도 있으면 축척 기준 영역은 **블록뿐** — 사인물의 입력 치수는 기준에서 빠진다(입력값은 그대로 보이고 견적에 쓰임). 블록은 정한 축의 면에서 잰다(`faceSizeOnAxis` — y 벽면, x 벽에 직각인 세로면, z 수평면; 축이 없거나 그 면에서 못 재면 벽면). 원근이 없으면 첫 치수 있는 블록이 기준 영역(같은 평면).
- **여러 사진에 쓰인 사인물**(`sameAs`): 치수를 넣지 않았으면 예상 크기는 블록 있는 사진의 추정 — **마지막으로 블록을 고친 사진**(`app.lastBlockPhotoId`) 우선, 그다음 자기 사진, 그다음 다른 사진("사인물이 다른 사진에도 사용되었다면 현재 조정하는 사진의 블록 변경을 따른다").
- **원근**(`blockCameraFit`): 블록을 고치면(그리기·치수·축·옮기기·지우기) 자동 원근(또는 원근 없음)인 사진은 **치수 있는 첫 벽면 블록**을 사인물처럼(원점·기준 길이·화각) 쓰고 나머지 블록의 변을 축 선으로 더해 다시 잡는다. 사인물 치수 입력의 자동 원근·[원근 자동 매칭]도 치수 있는 블록이 있으면 블록으로. 사람이 원근 창에서 맞춘 원근·자동 끔은 손대지 않는다.
- **축과 원근 선**(`blockLines`): 벽면 블록은 위·아래 변 = 가로(X), 좌·우 변 = 높이(Z). 옆면 블록은 좌·우 변(수직)만 Z. 수평 블록은 선에 넣지 않고 축척에만. 같은 축의 선이 셋 이상이면 최소제곱 소실점(정규화 좌표, 산포 행렬의 최소 고유벡터).
- **원근 완성도**: 치수 있는 벽면 블록도 사인물처럼 원근을 확인한다(라인·비율) → 3칸.
- 어느 면에도 딱 맞지 않는 사인물 외곽선은 벽면에서 잰다(비뚤게 그린 블록으로 원근이 조금 바뀌어도 추정이 사라지지 않게, 2026-11-04).

## 왜 효과가 있나
작은 기준 하나는 변이 거의 평행해 소실점이 흔들리고 그 오차가 2층으로 외삽된다. 크기를 아는 블록을 건물 여기저기(대각으로 이어 2층까지) 놓으면 축 선이 사진 전체에 퍼져 원근이 안정되고, 축척도 여러 블록이 정한다. 합성 사진 검증(`tests/unit/blocks.test.ts`): 366px 기준의 꼭짓점을 ±3px 흔들었을 때 2층 창문(참값 1500×1200)이 기준 하나로는 1717×1869, 블록 둘을 더하면 1449×1193. 크기가 서로 다른 블록 셋으로 잡은 원근은 3% 안.
