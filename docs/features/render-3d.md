# 입체 간판과 실사 렌더링

## 요약
4차(입체 간판): 채널 간판의 문구를 **실제 입체 글자(3D)**로 보여 주고, 폰트 기준 전체 폭을 치수에 넣습니다. 5차(실사 렌더링): 사진 속 벽면에 사인물을 합성해 주간 그림자·야간 발광을 바로 확인하고 PNG 로 저장합니다.

## 상태
- 4차 **구현됨** (2026-10-13)
- 5차 **구현됨** (2026-10-13) — 사진 보드 사진 이름 바의 [🧊 3D] (2026-10-14 "3D 뷰"로: 사인물이 없어도 열림)

## 입체 보기 (4차)
- 조건: **채널 옵션**(전광·후광·전후광·갈바 에폭시; 2026-10-15 부터 채널은 간판 종류가 아니라 몸통의 옵션)이 있고 문구·글자 높이(옵션 `chHeight`, 없으면 간판 높이)가 있을 때 사인물 설정 창([설정])에 [입체 보기 (3D)]가 나타납니다.
- 창(`src/lib/ui/Letter3DDialog.svelte`): Three.js 로 글자를 돌려 보고(OrbitControls) 주간/야간 전환, PNG 저장. 고객(viewer)도 열어 볼 수 있고 설정은 바꿀 수 없습니다.
- 글자: Pretendard Bold 윤곽(`core/textShapes.ts`) → `ExtrudeGeometry`(`sim/signs.ts`). 전광(`ch-front`)은 면 발광, 후광(`ch-halo`)은 벽면 반사 글로우, 그 외 비조명(`lightingOf`).
- 설정은 사인물 `letter3d { depthMm, faceColor, sideColor, letterSpacing }`에 저장(기본 두께 80mm). 바꾸면 모두에게 반영.
- **폰트 기준 폭**: 글자 높이·자간으로 조판한 전체 폭(mm)을 계산해 보여 주고(`measureTextWidthMm`), [가로 치수에 적용]으로 10mm 단위 반올림해 넣습니다 → 채널 견적의 근거가 됩니다.

## 보드 3D 단계 (2026-10-15 사용자: "3D 는 화면에 바로 올리고, 렌더링은 현재 3D 버튼을 대신해서 사진마다")
- 상단 **[원본 | 3D]**(`stage-original/-3d`, 보드 뷰에서만, `app.stage`). **원본** = 실측·편집(지금까지의 보드). **3D** = 모든 사진 위에 합성 결과(PNG)를 겹쳐 보여 줌(`photo-overlay`): 영역·핸들·디자인 레이어는 숨고 편집 도구는 선택·핀만.
- **부하**: `render/scene.ts` `StageRenderer` — WebGL 뷰어 **하나**를 켜 둔 채 사진을 **차례로** 그리고(동시에 여러 WebGL 없음), 사진마다 **내용 키**(`app.stageKey`: 영역·종류·옵션·문구·치수·연결·카메라)가 바뀐 것만 300ms 뒤에 다시 그립니다. 디자인 이미지는 입히지 않고 사진 긴 변 ≤ 640px 로 그려 가볍습니다. 원본 단계로 돌아오면 뷰어를 버립니다(`dispose`). 합성 중에는 "3D 합성 중… (n)"(`stage-status`). 3D 벽면이 없는 사진(원근·치수 없음)은 원본 그대로.
- **렌더링**: 사진 머리글의 [🎨 렌더링](`render-open`, 옛 🧊 3D 버튼 자리)이 아래 "렌더링 창"(옛 3D 뷰 창: 디자인 포함 최종 합성, 주간·야간, 격자, PNG 저장)을 엽니다. 제안 이미지도 같은 규칙.
- E2E: `tests/e2e/stage.spec.ts`.

## 앞면은 항상 카메라 쪽 (2026-10-15)
사용자: "정면 페이스가 사라졌다". 원근에 맞는 사인물을 원근 설정의 카메라로 그리면서, 원근 창의 축 지정(예: 첫 쌍 −X, 또는 첫 쌍 Z)에 따라 그 카메라의 **+z 가 벽 안쪽**이 되는 경우가 있었습니다 — 상자가 벽 속으로 밀려 앞면(채널 글자·디자인)이 상자 뒤에 가려짐. 이제 사인물마다 투영으로 +z 가 카메라 쪽인지 보고(`zTowardCamera`), 아니면 상자를 z 로 뒤집어(`group.scale.z = -1`, Three 가 면 방향을 맞춰 줌) 앞면이 카메라를 보게 합니다. 렌더링 창·3D 단계·제안 이미지 공통. E2E: `tests/e2e/render.spec.ts`(축을 뒤집은 카메라에서 빨간 채널 글자가 보이는지 — 수정 전 0픽셀).

**축 리버스 시 뒤집힌 단면 (2026-10-15)** — 사용자: "원근에서 x축 방향으로 리버스하면 3d가 뒤집어진다". 축 하나를 리버스(−X 또는 −Z)하면 벽 좌표가 거울상이라 그린 사각형의 꼭짓점이 좌우(또는 상하)로 뒤집혀 놓입니다. `warpToQuad` 가 이 평면 안 호모그래피를 정점에 직접 굽기 때문에 삼각형 감김이 반대가 되어, 앞면 대신 글자 안쪽 면이 그려졌습니다(Three 는 객체 행렬의 거울상만 보정하고 정점에 구운 거울상은 모름). 이제 중심의 야코비안 부호(det H / d³ < 0)로 거울상을 알아내 삼각형 감김을 되돌립니다(`reverseWinding`). 단위 테스트: `tests/unit/warpToQuad.test.ts`(가로·세로 거울상에서 앞면 감김이 +z).

## 반사광으로 앞면이 씻기지 않게 (2026-10-15)
같은 신고("정면 페이스가 사라졌다")의 운영 측면 사진: 몸통(갈바) 위 전광 채널 "바로바로정육점"의 왼쪽 글자 앞면이 하얗게 씻겨 테두리만 보였습니다. 원인은 기하가 아니라 **광택**: 상자 앞면(clearcoat 0.5, roughness 0.3)과 채널 앞면(clearcoat 0.6, roughness 0.25)의 정반사 하이라이트가 비스듬한 사인물에서 앞면 절반을 덮음. 앞면 재질을 무광에 가깝게(roughness 0.6~0.65, clearcoat 0.1) 바꿈. 테두리·옆면 금속 질감은 그대로. E2E: 운영 측면 사진의 외곽선·치수(6400×600) 그대로 왼쪽 글자도 빨간지(`tests/e2e/render.spec.ts`, 수정 전 0). 함께 확인: 입력 가로는 자신의 면으로 그릴 때도 회전에 영향이 없음(`signPlane.test.ts`).

## 렌더링 창 (옛 3D 뷰, 5차 실사 보기 → 2026-10-14 사용자: "우선 3D 뷰가 있어야 한다, 사진마다 3D 가능한지 먼저 확인")
- 사진마다 이름 바에 **[🧊 3D]**(`render-open`, `data-status` = `ok`/`none`): 원근 설정이 있거나 치수를 입력한 사인물이 있으면 ✓(`app.threeDOk`). 사인물이 없어도 열리고, 벽면 격자(1m)·원점 축(가로 X 빨강·높이 Z 파랑·세로 Y 초록)·1m 상자를 사진 위에 그려 **이 사진의 3D 가 맞는지** 먼저 확인합니다. 3D 가 안 되는 사진은 이유와 [원근 맞추기] 버튼(`render-open-camera`)을 보여 줍니다. → `RenderDialog.svelte`(`app.renderPhotoId`). 주간/야간, 벽면 격자, [PNG 저장](원본 해상도, 긴 변 4096 제한). Esc·바깥 클릭으로 닫힘.
- **벽면 좌표계** (`src/lib/core/wallPlane.ts`): 사진 px ↔ 벽면 mm(X 오른쪽, Y 위, 원점 = 영역들의 좌하단).
  - **카메라 설정**이 있는 사진 → 그 벽면(`calibrationOf` → `Calibration.H`). 축 방향은 첫 영역의 TL→TR 이 +x, BL→TL 이 +y 가 되게 맞춥니다.
  - 카메라 보정은 `metric: true` — 사진 px → 벽 mm 가 원점·방향까지 맞아 사인물 없이도 벽면이 됩니다(원근 창의 3D 겹침과 같은 격자).
  - 아니면 **치수를 입력한 첫 영역**을 벽면 기준(실측 판독과 같은 규칙).
  - 그것도 없으면 **그린 영역 그대로**(`drawn`, 2026-10-14 사용자: "사진 위의 사인물 크기는 사용자가 그린 사인물에 맞물리면 된다… 입력 크기에 따라 3D 가 바뀌는 건 필요 없다"): 첫 영역의 높이를 1000mm 로 두고 가로는 영역 비율. 3D 는 그려진 자리에 그 비율대로 놓이고, 입력 치수는 제작용 메모일 뿐 3D 위치·크기를 바꾸지 않습니다. 사인물 영역이 하나도 없을 때만 "3D 를 만들 수 없습니다".
  - **사인물 하나가 실패해도 나머지는 그립니다**(2026-10-14 사용자: "처음 만든 사인물은 나오고 이후 만든 것은 안 나온다" — 한 사인물의 입체 글자 생성 실패(폰트에 없는 글자·공백만 등)가 전체를 멈추던 문제): 실패한 사인물은 상자로 대신하고 3D 뷰 상태에 이유를 적습니다(`render-status`). `channelGeometry` 는 윤곽이 없으면 명확한 오류를 던집니다.
  - **간판 천갈이**(`board-reface`)는 후렉스 간판과 같은 전광 상자로 놓입니다(기존 프레임에 원단만 교체).
  - **돌출 간판**(`board-protrude`)은 그린 면에 전광 상자(후렉스와 같은 외형)로 놓입니다. 벽에 수직으로 튀어나온 방향·양면 표현은 후속(그린 영역 = 옆에서 보이는 면이라는 가정).
  - **사인물마다 자기 카메라**(`Viewer.addSignCamera`, `SignsPass`): 사인물은 자기 영역의 벽면(`wallPlaneOf([o])`: 치수 있으면 mm, 없으면 비율)으로 만든 투영을 가진 카메라로 자기 레이어만 덧그립니다. 격자·그림자 면은 사진의 카메라(레이어 0). 그래서 사진의 카메라가 바닥 평면으로 잡혔거나 사인물이 그 평면의 지평선 너머(깊이 ≤ 0)라도 사인물은 그린 자리에 보입니다(E2E: 둘째 쌍을 세로 Y 로 둔 카메라 + 벽 위쪽 박스). 최대 31개, 넘으면 메인 카메라.
  - **그린 사각형에 정확히 맞춤**(`warpToQuad`, 2026-10-14 운영 프로젝트 점검: 네 사진 모두 기본 원근이 손대지 않은 채 적용되어 있어 사인물이 카메라 벽면의 직사각형으로 해석돼 엉뚱한 곳에 그려졌음): 사인물의 네 꼭짓점을 벽면 좌표로 보낸 일반 사각형(`quadOnWall`)에 평면 안 호모그래피로 정점 x,y 를 맞춥니다(z 두께는 그대로). 카메라가 벽과 어긋나도 사인물은 그린 자리에 놓이고, 카메라가 맞으면 변형은 거의 0 입니다.
  - **입체 글자 폭 맞춤**(`fitScale`): 문구를 폰트로 조판한 폭이 그린 영역보다 넓으면 영역 폭에 맞게 줄입니다(좁으면 그대로). 박스·시트는 영역 크기 그대로.
  - `placeOnWall`: 영역 사각형 → 벽면 중심·크기(위·아래 변 평균 = 가로, 좌·우 변 평균 = 세로). 원형·다각형도 외곽 사각형으로.
  - `poseOfPlane`: 벽면 4000mm 정사각형의 사진 투영 → 초점거리 추정(`estimateFocal`, 실패 시 장변×0.75) → `recoverPose`. 셰이딩용 카메라 위치·회전에 씁니다.
  - **`projectionFromPlane`** (2026-10-14 사용자: "새로 만든 사인물이 엉뚱한 곳에 있다"): 핀홀로 분해한 카메라는 손으로 그린 영역처럼 핀홀과 맞지 않는 H 에서 먼 사인물을 제자리에서 벗어나게 했습니다. 그래서 정점 변환은 **H 에 정확히 맞는 3×4 투영**을 씁니다 — X·Y·평행이동 열은 H 그대로(z=0 평면 오차 0), Z 열만 추정 K 로 만든 r₃(AR 마커 방식, 벽 밖이 카메라 쪽이 되게 부호). 뷰어 `applyProjection` 이 이를 클립 행렬 [ (2/W)P₀−P₂ ; −(2/H)P₁+P₂ ; aP₂+b ; P₂ ] 로 바꿔 `projectionMatrix = M·matrixWorld` 로 넣습니다(깊이는 h₃₃=1 정규화 때문에 단위 없는 ~1 값 — near 바닥값을 두면 전부 잘리는 실수를 했었음). 단위 테스트: 손으로 찍은 사각형에서도 벽 위 점이 1e-6 안, 핀홀 사진에서는 Z 가 있어도 복원 포즈와 3px 안, 벽 점들이 near~far 안.
- **사인물 → 3D 사양** (`src/lib/core/render.ts` `renderSpecOf`, `signParts` 로 몸통·채널 분리): 몸통 없음 + 채널 + 문구 = 입체 글자만(글자 높이 = 영역 세로, 4차의 두께·색·자간 설정 사용, 전광·후광 조명). **몸통 + 채널 + 문구 = 상자 위에 입체 글자**(`SignSpec.letters`, `buildSign`: 글자를 상자 앞면(z = 두께)에 폭 90% 안으로 맞춰 가운데, 글자 높이는 옵션 비율·없으면 영역 세로의 60%). 분류가 없는 사인물도 회색 판(20mm)으로 자리를 보여 줍니다(2026-10-14: 사진마다 그린 사인물이 3D 에서 빠지지 않게). 그 외 = 박스(`lightboxGeometry`: `corner` 가 있으면 둥근 사각형을 밀어낸 형상, 면 이미지 UV 는 repeat/offset 으로 0~1 맞춤): 보드는 제품별 바탕색·두께(포맥스 10 / 복합판·아크릴·갈바 100 / 플렉스 150, 플렉스만 발광), 시트만이면 2mm 얇은 면. 문구가 있으면 면에 글자, **입힌 디자인(UV 뷰)**이 있으면 그 이미지를 면에 붙입니다(`buildLightbox(spec, font, face)`). 분류 없는 사인물은 그리지 않습니다.
