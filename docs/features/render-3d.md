# 입체 간판과 실사 렌더링

## 요약
4차(입체 간판): 채널 간판의 문구를 **실제 입체 글자(3D)**로 보여 주고, 폰트 기준 전체 폭을 치수에 넣습니다. 5차(실사 렌더링): 사진 속 벽면에 사인물을 합성해 주간 그림자·야간 발광을 바로 확인하고 PNG 로 저장합니다.

## 입체 보기 (4차)
- 조건: **채널 옵션**(전광·후광·전후광·갈바 에폭시; 2026-10-15 부터 채널은 간판 종류가 아니라 몸통의 옵션)이 있고 문구·글자 높이(옵션 `chHeight`, 없으면 간판 높이)가 있을 때 사인물 설정 창([설정])에 [입체 보기 (3D)]가 나타납니다.
- 창(`src/lib/ui/Letter3DDialog.svelte`): Three.js 로 글자를 돌려 보고(OrbitControls) 주간/야간 전환, PNG 저장. 고객(viewer)도 열어 볼 수 있고 설정은 바꿀 수 없습니다.
- 글자: Pretendard Bold 윤곽(`core/textShapes.ts`) → `ExtrudeGeometry`(`sim/signs.ts`). 전광(`ch-front`)은 면 발광, 후광(`ch-halo`)은 벽면 반사 글로우, 그 외 비조명(`lightingOf`).
- 설정은 사인물 `letter3d { depthMm, faceColor, sideColor, letterSpacing }`에 저장(기본 두께 80mm). 바꾸면 모두에게 반영.
- **폰트 기준 폭**: 글자 높이·자간으로 조판한 전체 폭(mm)을 계산해 보여 주고(`measureTextWidthMm`), [가로 치수에 적용]으로 10mm 단위 반올림해 넣습니다 → 채널 견적의 근거가 됩니다.

## 보드 3D 단계 (2026-10-15 사용자: "3D 는 화면에 바로 올리고, 렌더링은 현재 3D 버튼을 대신해서 사진마다")

- **부하**: `render/scene.ts` `StageRenderer` — WebGL 뷰어 **하나**를 켜 둔 채 사진을 **차례로** 그리고(동시에 여러 WebGL 없음), 사진마다 **내용 키**(`app.stageKey`: 영역·종류·옵션·문구·치수·연결·**구성 요소(정면도 배치)**·**입힌 디자인**·카메라 — 2026-10-17 "3d가 아직 정면도의 변경을 따르지 않는다": `parts` 가 키에 빠져 있어 정면도를 고쳐도 다시 그리지 않던 버그)가 바뀐 것만 300ms 뒤에 다시 그립니다. 디자인 이미지도 입히고(2026-10-17 사용자: "3d에서는 이미지 맵이 들어오지 않았다" — 전에는 가볍게 하려고 뺐음) 사진 긴 변 ≤ 640px 로 그려 가볍습니다. 원본 단계로 돌아오면 뷰어를 버립니다(`dispose`). 합성 중에는 "3D 합성 중… (n)"(`stage-status`). 3D 벽면이 없는 사진(원근·치수 없음)은 원본 그대로.
- **렌더링**: 사진 ⚙ 메뉴의 [렌더링](`render-open`, 2026-11-08 — 머리글 자리는 [☀ 주간 / 🌙 야간] 토글 `photo-night`: 사진보드 3D 를 야간으로, 3D 그림 키에 `night`)이 아래 "렌더링 창"(옛 3D 뷰 창: 디자인 포함 최종 합성, 주간·야간, 격자, PNG 저장)을 엽니다. 제안 이미지도 같은 규칙.

## 실시간 3D — 화면 가운데 사진만 (2026-10-27)
> 층 구조·LOD·휴대폰 한도·사고 기록을 모은 정리: [architecture/rendering-lod.md](../architecture/rendering-lod.md)

사용자: "3d 랜더링보다 실시간이 더 빠르지 않나?" → "확대할때 이상해 화면에서 가운데 있는 사진의 3d만 실시간".
전엔 3D 단계가 사진마다 장면을 통째로 짓고 폭 1,280px 로 그려 PNG(data URL)로 바꿔 겹쳤다 — 바꿀 때마다 차례로 다시 만들어 늦고, 확대하면 그 그림을 늘려 흐렸다.
- **가운데 사진 하나만 실시간**(`core/liveView.ts liveView`): 화면 가운데가 들어간 사진(없으면 가장 많이 보이는 사진, 3D 벽면이 있는 것만). 나머지 사진은 위 합성 그림 그대로.
- **보이는 부분만 화면 해상도로**: 그 사진에서 화면에 보이는 조각(원본 픽셀 `crop`)을 화면 크기(`px`)로 그린다 — `Viewer.setCrop`: 배경 사진 셰이더의 uv 와 모든 카메라(메인·사인물별)의 투영 뒤에 화면 자르기 행렬(NDC 확대·이동)을 곱한다(`SignsPass.draw`). 그래서 크게 확대해도 그림이 화면보다 커지지 않고(휴대폰 메모리 안전) 또렷하다. 앞면 그림(인쇄 글자·디자인)은 실시간에서 긴 변 **3072px**(휴대폰 2048, PNG 는 1024 그대로 — `LIVE_TEX_LONG`).
- **장면은 내용이 바뀔 때만 다시**(`LiveStage.build`, 사진 내용 키 `stageKey`), 화면 이동·확대는 자르기·크기만(`frame`). 움직이는 동안은 숨겨 합성 그림이 보이고, 멈추면(150ms) 다시 그린다.
- 자리: 보드 안 `live-3d`(사진 위 보이는 조각 자리, `scale(1/줌)`), 편집 층(svg)보다 아래, 누르기는 통과. 2D·실측으로 가면 없앤다. WebGL 은 합성 그림용 하나 + 실시간 하나.
- **휴대폰은 3D 화면 하나만**(2026-10-28 사용자: "3d에서 사진이 새로 3d랜더링이 되려는 시점에 리프레시된다" → "핀볼에서 확인해봐"): 휴대폰은 합성 그림(PNG)을 만들지 않고 **가운데 사진만 실시간** — 가운데가 아닌 사진은 사진 그대로. 전엔 합성 그림용 3D 화면을 사진마다 만들었다 버리며 실시간과 겹쳐 3D 화면이 둘이 됐다(아이폰 사파리는 3D 화면을 만들고 버리기를 되풀이하면 메모리를 늦게 돌려줘 페이지를 다시 연다). 그림자 버퍼도 휴대폰은 1024. 핀볼 사본 휴대폰 화면 확인: 사진 4장을 차례로 가운데로 8번 — 3D 화면 최대 2개 → 1개, 오류·다시 열림 없음, 장면 사진·사인물 수 일치.
- **LOD — 저장된 그림 + 실시간 3D 를 눈치채지 못하게**(2026-10-29 사용자: "아직 화면 줌아웃과 사진보드 리플레시 문제는 해결되지 않았다 … lod … 시트처럼 2d인 경우는 3d로 변환할 이유가 없다. 사인물을 변경한 경우가 아니라면 기존의 저장된 이미지를 사용한다 … 사용자가 눈치채지 못하게 … 2d도 이동하거나 변경하면 사라졌다 다시 나타난다"):
  - **저장된 3D 그림**(`render/stageCache.ts`, IndexedDB `ganpanda-derived` 의 `s3|<사진>|<내용 키>` JPEG): 내용 키(`stageKey` — 사인물·카메라가 바뀌면 바뀐다)가 같으면 다시 만들지 않는다 — 다시 열어도, 줌아웃·인 해도. 전엔 열 때마다 모든 사진을 다시 합성했다. 데스크톱은 합성 줄(`StageRenderer`, 이제 JPEG)이 만들어 저장, **휴대폰은 따로 만들지 않고 가운데 사진의 실시간 화면에서 떠서**(`LiveStage.snapshot` — 그림판 크기 그대로 사진 전체를 그려 사진 비율로 옮김) 저장 — 3D 화면은 여전히 하나. 새로 만든 횟수 `app.stageMade`.
  - **LOD 층**: 사진 → 저장된 3D 그림(모든 사진) → 가운데 사진의 실시간 3D(투명도 0.22초로 겹쳐 나타나고 사라짐). 같은 그림이라 바뀌는 순간이 보이지 않는다. 가운데 사진이 바뀌는 순간엔 실시간을 바로 숨기고(엉뚱한 자리에 앞 사진이 남지 않게) 새 장면이 얹히면 부드럽게.
  - **납작한 사진은 3D 안 함**(`core/stageFlat.ts needs3d`): 시트·현수막뿐(또는 분류 없는 외곽선뿐)이면 합성 그림·실시간 없이 3D 단계에서도 **2D 그림 층** 그대로.
  - **2D 두 손가락 조작**: 원근으로 겹친 그림(`.warp`)을 숨기던 것(2026-10-21 크래시 대응)을 **숨기지 않고 `will-change: transform`** — 사파리는 움직이는 동안 지금 그림을 늘려 쓰고 손을 떼면 또렷하게 다시 그린다. 층 크기는 이미 `capBox` 로 제한돼 있다(2026-10-21).
  - **2D 원근 층은 구운 그림 하나로**(2026-10-29 사용자: "아이폰앱에서 2d에서 줌인 줌아웃을 하면 에러가 발생한다" — 핀볼 사본에서 확인): 사인물마다 글자·그림 DOM 층(`matrix3d`)이 20개쯤 있었고 1200% 에서 층이 화면 약 9,500px 로 커져 WebKit 메모리를 넘겼다. 이제 구성 요소(`render/bake2d.ts` `bakeParts`, PNG)·입힌 디자인(`bakeDesign`, JPEG)을 **긴 변 최대 1024px 그림으로 한 번 굽고** `<img>` 하나에 원근 변환(`ui/BakedParts.svelte`·`BakedDesign.svelte`). 내용 키가 같으면 다시 굽지 않고, 다시 굽는 동안은 앞 그림을 그대로 둔다(사라졌다 나타나지 않게). 글자 그리기는 3D 와 같은 `render/faceDraw.ts`. 테스트 `tests/e2e/stageLod.spec.ts`.
  - 핀볼 사본 휴대폰 화면: 끌기·두 손가락 줌 14번 — 다시 열림 없음, 3D 화면 1개, 3D 그림은 사진마다 한 번만 만들고(3장 → 3번) 그다음은 저장된 그림. 테스트 `tests/e2e/stageLod.spec.ts`, `tests/unit/stageFlat.test.ts`.
- **움직이는 동안에도 실시간**(2026-10-28 사용자: "3d가 실시간으로 랜더링 보이느게 어려운건가?" → "진행해봐"): 그림판(WebGL 캔버스·버퍼)은 **보드 화면 크기로 고정**하고(창 크기가 바뀔 때만 다시 만든다), 화면에는 CSS 로 보이는 조각 크기에 맞춘다 — 화면을 끌거나 확대하는 동안 숨기지 않고 매번 자르기만 바꿔 바로 다시 그린다(전엔 숨겼다가 멈추면 150ms 뒤 그렸다). 장면은 **준비**(`prepareScene`: 사진 텍스처·사인물 만들기, 뷰어는 안 건드림)와 **얹기**(`applyScene`)로 나눠, 지은 장면을 사진마다 **기억**(휴대폰 2 · 그 외 4, 오래된 것부터 버림) — 다시 가운데로 오면 바로. 데스크톱은 쉬는 동안 화면에 보이는 가까운 사진 2장을 미리 짓는다. 디자인 그림은 사인물 것을 한꺼번에 받고 사진 하나에 최대 **2.5초**만 기다리며(`LIVE_ASSET_WAIT_MS`), 한 번 늦은 그림은 1분 동안 다시 기다리지 않는다 — 못 받는 그림 하나 때문에 장면 줄이 멈추던 것(핀볼 사본에서 ~18초). 안개 시트 층은 실시간 3D 위(z 2). 핀볼 사본 확인: 데스크톱은 끄는 중에도 합성 그림과 겹쳐 맞음, 휴대폰은 끌기·두 손가락 줌 10번 동안 다시 열림 없음 · 3D 화면 1개 · 매번 바로 그 사진 장면.
  - **휴대폰은 대체됨(2026-10-29)**: 아이폰에서 화면 이동을 반복하면 다시 열려(안드로이드·맥 크롬은 괜찮음) 휴대폰은 **화면이 300ms 멈춘 뒤에** 새 장면을 짓고(움직이는 동안은 저장된 3D 그림), 기억하는 장면 1개, 앞면 텍스처 1024, 버린 장면 캔버스는 바로 비운다. 자세히 → [architecture/rendering-lod.md](../architecture/rendering-lod.md) "아이폰 방지 장치 되살림".

## 앞면은 항상 카메라 쪽 (2026-10-15)
사용자: "정면 페이스가 사라졌다". 원근에 맞는 사인물을 원근 설정의 카메라로 그리면서, 원근 창의 축 지정(예: 첫 쌍 −X, 또는 첫 쌍 Z)에 따라 그 카메라의 **+z 가 벽 안쪽**이 되는 경우가 있었습니다 — 상자가 벽 속으로 밀려 앞면(채널 글자·디자인)이 상자 뒤에 가려짐. 이제 사인물마다 투영으로 +z 가 카메라 쪽인지 보고(`zTowardCamera`), 아니면 상자를 z 로 뒤집어(`group.scale.z = -1`, Three 가 면 방향을 맞춰 줌) 앞면이 카메라를 보게 합니다. 렌더링 창·3D 단계·제안 이미지 공통. E2E: `tests/e2e/render.spec.ts`(축을 뒤집은 카메라에서 빨간 채널 글자가 보이는지 — 수정 전 0픽셀).

**간판 상단 조명 자동 모델 (2026-10-16)** — 사용자: "간판에 상단에 돌출 조명, 트러스트바형식의 간접조명, 트러스트 타공조명 등을 자동 모델링 할 수 있나?" → "진행해줘". 간판 사양의 `topLight`(종류·개수·팔 길이·빛 색)로 `topLightMeshes`(`sim/signs.ts`)가 사인물 좌표(가로 중심, 위 끝 h/2, 앞면 z=d)에 부품을 만들고 `buildSign` 이 붙입니다. 돌출 투광등: 간판 위에서 앞으로 뻗는 팔 + 간판 쪽으로 숙인 등기구를 가로로 고르게, 밤에는 등기구가 빛나고 간판 위쪽 1/3 로 향하는 빛 줄기(더하기 합성 원뿔)와 면 번짐. 트러스 바 간접조명: 간판 가로 전체의 바(45×70mm) + 아래를 비추는 LED 띠, 밤에는 위가 밝고 아래로 사라지는 면 번짐(정점 색). 트러스 타공 조명: 어두운 바 + 120mm 마다 점 조명. 그린 사각형 맞춤(`warpToQuad`)이 정점에 적용되므로 모든 부품의 변환은 정점에 굽고 메쉬는 위치·회전 없이 둡니다(박스 방향 기울임·뒤집기도 그대로 따라감). 함께: 후렉스·돌출 등의 내부 조명 옵션이 "비조명"이면 3D 상자도 빛나지 않습니다(상단 조명은 주로 비조명 간판에). 테스트: `tests/unit/topLight.test.ts`.

**박스 방향 (2026-10-15)** — 사용자: "박스만 회전하고 크기는 외곽선만". 사인물 면·크기(`sizedAt`·`contentSizeOf`: 구도로 정한 면에서 잰 크기, 정면 축·입력 치수와 무관)는 그대로 두고, 상자의 두께만 박스 방향(`boxLocalDirOf`: 회전 고리 `boxDir` > 평면 판 `faceAxis` > 면의 법선)으로 기울입니다(`orientBox`: 면 좌표 z 를 그 방향으로 보내는 기울임 행렬, 카메라 쪽, 방향이 면과 거의 나란하면 z 성분 0.15). 법선이면 예전의 뒤집기와 같습니다.

**축 리버스 시 뒤집힌 단면 (2026-10-15)** — 사용자: "원근에서 x축 방향으로 리버스하면 3d가 뒤집어진다". 축 하나를 리버스(−X 또는 −Z)하면 벽 좌표가 거울상이라 그린 사각형의 꼭짓점이 좌우(또는 상하)로 뒤집혀 놓입니다. `warpToQuad` 가 이 평면 안 호모그래피를 정점에 직접 굽기 때문에 삼각형 감김이 반대가 되어, 앞면 대신 글자 안쪽 면이 그려졌습니다(Three 는 객체 행렬의 거울상만 보정하고 정점에 구운 거울상은 모름). 이제 중심의 야코비안 부호(det H / d³ < 0)로 거울상을 알아내 삼각형 감김을 되돌립니다(`reverseWinding`). 단위 테스트: `tests/unit/warpToQuad.test.ts`(가로·세로 거울상에서 앞면 감김이 +z).

## 반사광으로 앞면이 씻기지 않게 (2026-10-15)
같은 신고("정면 페이스가 사라졌다")의 운영 측면 사진: 몸통(갈바) 위 전광 채널 "바로바로정육점"의 왼쪽 글자 앞면이 하얗게 씻겨 테두리만 보였습니다. 원인은 기하가 아니라 **광택**: 상자 앞면(clearcoat 0.5, roughness 0.3)과 채널 앞면(clearcoat 0.6, roughness 0.25)의 정반사 하이라이트가 비스듬한 사인물에서 앞면 절반을 덮음. 앞면 재질을 무광에 가깝게(roughness 0.6~0.65, clearcoat 0.1) 바꿈. 테두리·옆면 금속 질감은 그대로. E2E: 운영 측면 사진의 외곽선·치수(6400×600) 그대로 왼쪽 글자도 빨간지(`tests/e2e/render.spec.ts`, 수정 전 0). 함께 확인: 입력 가로는 자신의 면으로 그릴 때도 회전에 영향이 없음(`signPlane.test.ts`).

## 렌더링 창 (옛 3D 뷰, 5차 실사 보기 → 2026-10-14 사용자: "우선 3D 뷰가 있어야 한다, 사진마다 3D 가능한지 먼저 확인")

- **번짐 세기**(같은 날 "돌출간판 라이팅 글로우 줄여주고 전광은 라이팅 글로우 높여줘"): 상자(돌출 등) 앞면 둘레 번짐 0.35 → **0.15**. 전광 채널 번짐은 **보통 섞기**(색을 덮음 — 더하면 밝은 판 위에서 흰+빨강 = 분홍) · 세기 1 · 넓고 진하게(흐림 0.3·0.12·0.04 × 글자 높이, 3번 겹쳐 그림 `passes`). 후광은 벽을 밝히는 빛이라 더하기 그대로.
- **상자 번짐은 앞면 그림 색대로**(같은 날 "돌출간판의 라이팅 글로우가 컬러과 관계없이 나온다. 흰색영역에서 글로우가 생겨야 맞다. 버건디 컬러에서는 버건디 컬러로 글로우가 약하게"): 바탕색 한 가지로 번지던 것을 앞면 그림(디자인 포함)을 아주 작게 줄였다 넓게 키운 흐린 색 번짐으로(`faceGlowTexture`, 둥근 모양으로 잘라서) — 더하기 빛이라 흰 곳은 밝게, 버건디는 버건디로 약하게. 세기 0.3. 테스트 `tests/e2e/photoToggles.spec.ts`(흰색·버건디 반반 앞면).
