## 일러스트 기준 정의 (2026-11-06)
카드 = 실측(사진) · 2D(속성 내용) · 3D(속성 내용 + 3D) · 디자인(대지 이미지). 보내기 = 카드마다 최종 이미지(3D 제외 마지막 단계). 스크립트 = 크기대로 대지 + 레이어 받은 이미지·디자인·path. 가져오기 = 디자인은 대지 이름별 이미지로 카드에 바로, path 는 사용자가 구성물에 연결 → 자세히 [illustrator.md](illustrator.md#일러스트-기준-파일-싱크--정의-2026-11-06).

## 일러스트 ↔ 간판다 = PDF 하나 (2026-11-07)
일러스트 [내보내기]는 레이어가 살아 있는 PDF 를 저장만 한다. 간판다는 그 PDF 에서 대지별 **디자인 그림**(받은 이미지 레이어는 끔)과 맨 위 레이어별 **벡터**를 꺼낸다 — 검토에서 레이어마다 구성물(채널·스카시)을 고르면(이름에 "채널"·"스카시"가 있으면 미리) 확정할 때 그 구성물의 입체가 된다. **패스는 디자인 쪽 내용**(`SignObject.designItems[구성물 id]`)으로 들어가고 제안 내용(글자·지정 색)은 그대로 — 디자인 탭·고객·렌더링은 디자인 내용, 제안 탭·견적은 제안 내용(2026-11-08 "제안은 텍스트와 지정컬러가 디자인은 pdf에서 가져온 페스와 디자인으로 각각 보여야한다", 앞서 구성물 내용을 바꾸던 것은 대체됨. 예전 데이터는 열 때 패스를 디자인 쪽으로 옮긴다 `migrateDesignItems`). 자세히 [illustrator.md](illustrator.md).

## 받기 → 사진보드에서 검토 → [확정]

**사진보드 = 입체 제외 디자인, 카드 = 전체**(2026-11-07 "입체로 추가한 경우 사진보드에서는 입체 내용을 제거한 이미지로 사인물 카드는 현재와 동일하게"): [확정]할 때 입체로 연결한 레이어가 있으면 받은 PDF(검토하는 동안 메모리)에서 그 쪽을 **그 레이어를 끈 채 다시 그려** 숨은 디자인 파일(`derived`, 디자인 파일 목록에 안 보임)로 넣고 `SignObject.designBase` 로 — 디자인 탭의 사진 위(3D 앞면 그림·원근 없는 사진의 2D, `PhotoZone`·`render/scene.ts`)는 이것 — 2D·3D 탭은 디자인 전 임시 설정이라 디자인 없음(2026-11-07), 사인물 카드·보내기 최종 이미지는 `design`(전체). 디자인을 바꾸거나 떼면 `designBase` 도 지운다. 3D 저장 그림 키에는 있을 때만 들어간다(`design/convert.ts renderPdfPageWithout`, `state.applyDesignBase`).

**디자인 탭 = 3D**(2026-11-07 "디자인은 3d를 표시하게"): 디자인 탭을 누르면 사진보드가 3D 단계(입체 글자가 솟은 합성). 2D 는 [2D] 탭.

**지난번 연결 기억**(2026-11-07 "다시 불렀을때 이전 연결을 유지할 수 있나?"): [확정]할 때 고른 레이어 → 구성물(입체 안 함 포함)을 사인물에 기억(`SignObject.layerLinks`)하고, 다음에 받으면 그 연결을 미리 고른다 — 기억한 구성물이 없어졌으면 이름 추측("채널"·"스카시"·구성물 이름).

**받기가 실패하면**(2026-11-07 맥 앱 "파일을 처리하지 못했습니다" — 원인이 안 보였다): 알림에 **단계와 오류**("파일을 처리하지 못했습니다 (그림 저장: …)"), 앱 진단 기록(`crashLog` 사건)에도. 단계 = 파일 읽기 · 그림 저장 · 디자인 파일 등록 · 사인물 짝 찾기. 레이어 벡터·원본 파일 저장은 덤이라 실패해도 디자인 그림은 계속(원본을 못 넣으면 첫 페이지 그림이 원본 자리), 레이어 설정으로 못 그리면 설정 없이 다시 그린다. **실제 원인(2026-11-07)**: 맥 앱의 시스템 WebKit(macOS 26.1 JavaScriptCore)에는 pdf.js 6.x 일반 빌드가 대체 코드 없이 쓰는 `Map.prototype.getOrInsertComputed`·`Math.sumPrecise` 가 없어 PDF 를 여는 순간 실패했다(테스트용 WebKit·Chromium 은 더 새 엔진이라 통과) → `design/convert.ts` 는 **pdf.js legacy 빌드**(대체 코드 포함)와 그 worker 를 쓴다(`tests/unit/pdfjsCompat.test.ts`, e2e `pdfLayers.spec.ts` 기능을 지운 채 받기). 큰 PDF(예: 45MB)는 페이지를 그린 뒤 같은 연산 목록으로 벡터를 꺼내고 페이지마다 메모리를 비운다. 서버 파일 한도(25MB)를 넘는 원본은 서버에 올라가지 않는다(그림은 올라감).
받은 파일은 **바로 입히지 않는다**. 사진보드로 돌아가 오른쪽 위(휴대폰은 아래) **받은 디자인 검토** 패널(`ui/SyncReview.svelte`, `sync-review`)과 카드 표시로 확인하고 [확정](`sync-confirm`) 해야 바뀐다. [취소](`sync-cancel`)면 아무것도 입히지 않는다(올린 파일은 디자인 파일 목록에 남음).

상태(`core/designSync.ts`)와 고를 수 있는 처리(첫째가 기본):

| 상태 | 뜻 | 카드 표시 | 처리 |
|---|---|---|---|
| 연결 | 디자인 없던 사인물에 짝 | 초록 테두리·"연결" | 입히기 / 건너뛰기 |
| 바뀜 | 디자인이 있던 사인물에 새 디자인 | 파랑 테두리·"바뀜" | 입히기 / 기존 유지 — **짝 정보 없이 크기로만 맞은 것은 기본 "기존 유지"**(우연히 크기가 같은 파일이 덮지 않게) |
| 새로 생김 | 파일에만 있는 대지(짝 없음·지워진 사인물·같은 id 두 번째) | 카드 없음, 패널에만 "대지 n · 가로×세로mm" | **새 사인물로**(사진 없는 카드, 크기 = 대지 ÷ 짝지은 대지의 축척, 평면 구역 오른쪽에) / 건너뛰기 — 짝 정보 없이 남은 대지는 기본 "건너뛰기" |
| 누락 | 보낸(치수 있는) 사인물인데 파일에 없음 — 짝 정보가 있을 때만 판단 | 주황 점선·"누락" | 기존 유지 / 연결 해제 |

- **빈(투명) 디자인**(2026-11-07 핀볼): 받은 디자인 PNG 가 완전히 투명하면(`render/blankImage.ts`) 넣지 않고 줄 아래 ⚠ 경고(`sync-blank`), 다른 것이 없으면 줄 기본 처리는 건너뛰기.
- 일러스트 묶음(.ganpanda): 사인물별 한 줄(디자인·path). 디자인은 확정하면 바로 바탕 디자인으로. path 는 줄 아래 **path → [구성물]**(`sync-path`)에서 채널·스카시 중 고른다 — 하나뿐이면 미리 골라 두고, 안 고르면 넣지 않는다. 간판다에 없는 사인물은 "새로 생김"이지만 건너뛰기만. 묶음에 없는 사인물은 누락(연결 해제 = 바탕 디자인 해제).
- 짝 정보도 크기 짝도 없는 PDF 는 검토 없이 디자인 파일에만 넣는다.
- 확정하면 알림 "디자인 싱크 확정 — 입힘 n · 새 사인물 n · 연결 해제 n". 입힘은 디자인 이력에 남아 되돌릴 수 있다.
