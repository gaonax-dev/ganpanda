# 컨펌 — 깨끗한 사진보드 · 진행 동의 → 제작 · 완료 사진첩 · 참고 이미지 (설계, 2026-10-22)

## 요약
사용자(2026-10-22): "컨펌은 사진뷰어와 같은데 가장 상위 단계가 보이고 사인물에 체크하면 진행하는것이다. 그리고 컨펌은 진행동의와 완료로 탭을 구분하고 완료는 완료 사진첩이다. 최근 고객이 ai로 이미지를 제시하는 경우가 많은데 이건 어디에 담으면 좋을까?" → "사진뷰어가 아니고 사진보드와 같은데 이런저런 표시없이 사인물(러프포함) 디자인과 사진에 올라간 상태가 있고 여기에 진행동의를 누르면 제작을 한다."

작업 탭 [사진보드 · 디자인 · 사인물리스트 · **컨펌**]의 컨펌은 **사진보드와 같은 화면에서 작업 표시를 모두 뺀 것** — 사진 위에 사인물(러프 디자인 포함)과 디자인이 올라간 모습만. 여기서 **[진행 동의]**를 누르면 **제작**으로 넘어간다. 안은 **[진행 동의 | 완료]** 두 탭.

## 상태
| 단계 | 내용 | 상태 |
|---|---|---|
| C1 | 컨펌 = 깨끗한 사진보드(표시 없이 사인물·디자인이 사진 위에), [진행 동의] → 제작 | 구현됨 (2026-10-22) → **작업 탭의 컨펌 화면은 같은 날 제거**("기존의 컨펌은 제거한다"). 고객 제안 페이지의 [진행 동의](사인물 빼기, 진행중 전환)는 그대로 |
| C2 | [완료] 탭 = 완료 사진첩(시공 후 사진, 현장 사진과 따로) | 계획 |
| C3 | 참고 이미지(고객 AI 이미지 등) 모음 — 디자인 탭, 사인물 연결, 견적 요청 첨부 | 계획 |

## 진행 동의 (C1)
- **화면 = 사진보드, 표시 없이**: 같은 보드(사진 배치·확대·이동 그대로)에서 **외곽선·치수·핸들·이름표·경고·말풍선 핀·평면도 카드·도구 막대를 모두 숨기고**, 사진 위에 **사인물이 올라간 모습만** — 디자인이 연결된 것은 디자인, 아직이면 러프 디자인(글자·그림·바탕색, 2D 합성). 3D 합성이 있으면 그것으로 보여도 된다(가장 앞선 모습). 러프 디자인은 "러프" 꼬리표만 작게(디자인 전이라는 것만 알게).
- **[진행 동의] → 제작**: 화면 아래 **[진행 동의]** 한 번 — 누가·언제·그때의 내용 해시를 남기고 프로젝트 상태가 **제작**(제작 중)으로 바뀐다. 동의 뒤 내용이 바뀌면 "다시 동의 필요"(지금의 승인·재승인 규칙 그대로). 사인물을 눌러 빼고 동의할 수 있게(일부만 진행) — 빠진 사인물은 흐리게, 동의 기록에 "제외".
- **누가**: 고객(제안 링크, 보기 권한)이 누르고 간판집은 동의 상태를 본다 — 고객은 문서를 고칠 수 없으므로 서버 RPC(지금의 `addApproval` 를 넓힘). 간판집이 대신 누르면 "간판집 기록".
- **지금 승인과의 관계**: 제안 페이지의 [이걸로 할게요]가 이 [진행 동의]가 된다 — 같은 화면을 간판집 작업 탭 컨펌과 고객 제안 링크가 함께 쓴다. 요청판의 [확정](간판집 고르기)은 따로 그대로.

### 구현 (2026-10-22)
- 작업 탭 [컨펌](`view-confirm`) → `app.confirmMode`: 같은 보드를 마지막 디자인 단계(2D/3D)로, `PhotoZone clean`(사진 머리·사인물 이름표·말풍선·작업 존·외곽선 없음, 눌러도 고르지 않음) + 보드의 도구 막대·평면도 카드 숨김 + 말풍선 핀·경고 끔. 강조색 파랑(제안 화면과 같음).
- 아래 **진행 동의 줄**(`ConfirmBar.svelte`, `confirm-bar`): 상태(동의 전·`✓ 진행 동의 … — 제작`·`⚠ 다시 동의 필요`), 사인물 칩(`confirm-sign`, 눌러서 빼기), [고객에게 보내기](제안 링크 창), **[진행 동의]**(`confirm-consent` — 간판집이 누르면 "(간판집 기록)").
- **사인물마다 멤버·고객 컨펌 — 정면도 카드 아래**(2026-10-22 사용자: "컨펌에 맴버컴펌도 필요하다" → "컨펌에 정면도 사인물 카드에 컨펌이 있어야한다. 현재방식은 대상을 파악하기 어렵다. 사인물마다. 고객과 맴버 컨펌"): 컨펌에서도 보드의 **정면도 카드**를 보이고(끌기 없음), 카드 아래 줄(`card-confirm`)에 **멤버**(`card-member`: ✓ 이름 · ⚠ 다시 확인 · 확인 전, [확인] `card-member-check`)와 **고객**(`card-customer`: 진행 · 제외 · 다시 동의 필요 · 동의 전, [빼기/포함] `card-skip` = 다음 진행 동의에서 뺄 것). 멤버 확인은 설정 `signChecks`(사인물 id → 확인들). **사인물마다 내용 지문**(`core/proposal.ts signHash`: 종류·옵션·문구·크기·디자인·구성 요소·그 사인물 금액, 자리는 뺌) — 그 사인물이 바뀔 때만 그 카드가 "다시 확인/다시 동의". 진행 동의 기록의 스냅샷에 `signHashes` 를 함께 남긴다(옛 동의는 전체 기준, `customerSignState`). 아래 줄은 요약(`confirm-summary`: 멤버 확인 a/n · 고객 동의 b/n · 뺄 것) + [진행 동의] + [고객에게 보내기](멤버 확인이 남으면 묻기). 컨펌에 들어가면 사진·카드가 줄 위로 보이게 맞춘다. (같은 날 먼저 넣은 프로젝트 단위 멤버 확인 `memberChecks`·아래 줄의 사인물 칩은 대체됨.) 고객 제안 페이지에는 멤버 확인이 안 보인다(내부 기록).
- 고객 제안 페이지: [이걸로 할게요] → **[진행 동의]**, 사인물 칩(`consent-sign`)으로 빼고 동의, 결과 "진행에 동의했습니다 — 제작을 시작합니다 (n개 제외)".
- 서버 `POST /api/rooms/:room/approvals {…, excluded?}`: 승인 기록에 `excluded`(뺀 사인물 id), 대화 메시지 "○○ 님이 진행에 동의했습니다 — 제작을 시작합니다", **프로젝트가 대기 중이면 진행중(제작)으로**(정지·완료는 그대로). 재동의 규칙은 지금의 승인 해시 그대로.

## 완료 사진첩 (C2)
- 시공이 끝난 뒤 올리는 사진 — **현장(실측) 사진과 따로** 모은다(원근·실측 대상이 아님). 사인물에 연결(어느 사인물의 완료 사진인지), 날짜·한 줄 설명.
- 고객 제안 페이지 [완료] 탭에서도 보이고, 간판집 포트폴리오(제안 페이지·견적 요청 응답의 실적)로 쓸 수 있게 둔다.

## 참고 이미지 — 고객의 AI 이미지 등 (C3)
**어디에**: 현장 사진(사진보드)도 디자인 파일(디자인)도 아닌 **"참고 이미지"** 모음을 따로 둔다. 사진보드에 섞이면 실측·원근 대상이 되고, 디자인 파일에 섞이면 최종 디자인으로 오해된다.
- **자리**: 디자인 탭 안 **[참고]** — 프로젝트의 무드보드. 이미지마다 **"이 사인물 참고"**로 사인물에 연결하면 그 사인물 설정 창·러프 디자인 작업 때 옆에 보인다.
- **들어오는 길**: 직접 올리기 · 대화 첨부에서 [참고 이미지로] · **견적 요청할 때 가게 사장이 첨부**(요청서·실측 보기에 같이 보임).
- **구분 표시**: 꼬리표 "참고 · 고객 제공"(AI 생성이면 "AI"), 디자인 리스트·주문서·견적에는 들어가지 않는다.
- 나중: 참고 이미지 위에 러프 디자인을 따라 그리기(반투명 바탕).
