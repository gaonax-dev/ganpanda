# 요청판 (견적 요청 → 가입 간판사 → 제안 링크)

## 요약
가게 사장이 **로그인 없이** 사진과 내용으로 간판 견적을 요청하면, 그 지역에서 **"요청 받기"를 켠 간판사**들에게 전달됩니다. 간판사는 요청에서 바로 프로젝트를 만들어(사진이 들어온 채로) 평소처럼 사인물을 그리고 **제안 링크**로 답합니다. 고객은 요청 페이지에서 받은 제안들을 나란히 보고 하나를 승인합니다. 계약·시공·돈은 고객과 간판사 사이에서 직접 — 간판다는 전달·기록만. 홍보자(아르바이트)는 자기 코드가 붙은 링크로 요청을 데려오고, 그 요청에 제안이 들어온 만큼 수수료를 받습니다(지급은 밖에서, 기록만). 결정 → [../product/decisions.md](../product/decisions.md) 2026-10-17, 과금 → [../product/pricing.md](../product/pricing.md).

## 사업자 확인·일반 주문·잠금·취소·재요청 (2026-10-22)
사용자: "견적요청 버튼 클릭하면 사업자등록확인 요청 대화식으로 등록증 요청한다. 하단에는 수동입력버튼도 준비한다. 이미지가 들어오면 내용을 추출하는 효과를 표현하고 완료되면 수동입력 폼이 나타나고 수집한 내용을 다시 확인한다. 사업자 확인이되면 사업자 인증 배지가 표시된 견적요청 페이지가 나온다. 만약 사업자없으면 일반 주문으로 표시하고 불이익도 안내해준다. 인증배지 옆에 변경도 만들어준다. 사업자 추가도 있어야한다. 선택가능하게. 견적요청 페이지는 견적 요청된 상태를 더 잘 포장해서. 그리고 "견적요청보내기" 왜 작동안하는지 모르겠다. 그리고 견적이 요청되면 수정이 불가능하다. 견적요청 취소 후 재 요청할수있다. 견적 입찰한 업체들은 토큰을 돌려받고 재 견적 간판다에서 요청을 보낸다."

- **읽는 효과**(`est-scanning`): 등록증 그림 위로 노란 빛줄이 오르내리고 오른쪽 칸(등록번호·상호·대표자·개업일·주소)이 반짝이다 읽은 값이 하나씩 채워진다(최소 0.9초 보이게). 끝나면 **확인 폼**(`est-confirm`, 읽은 값이 들어 있음 — 못 읽었으면 빈 칸과 안내) → **[확인하고 인증받기]**(`est-verify`) = 국세청 진위확인(번호·대표자·개업일) → 사업자 저장(사본도 사업자에 붙여 둠).
- **요청 폼**: 맨 위 **신원 줄**(`est-identity`, `data-kind` store|general) — "✓ 사업자 인증 · 상호 · 번호" 또는 "일반 주문", 옆에 **[변경]**(`est-identity-change`, 사업자 고르기·추가·일반 주문으로 돌아감). 고른 신원은 견적 초안 방 설정 `estimateIdentity` 로 기기 사이 같이. 일반 주문이면 **불이익 안내**(`est-general-notice`): 간판집이 허위 요청을 걱정해 제안이 적거나 늦을 수 있음, 세금계산서를 받을 수 없어 부가세 매입 공제 불가.
- **"견적요청보내기"가 안 되던 문제**: 단추가 조건(가게·전화·주소의 시/군/구·사진·사업자)이 모자라면 말없이 꺼져 있었다(운영에 요청이 한 건도 없었음). 이제 단추는 늘 눌리고, 모자라면 **빠진 것 목록**(`estimate-missing`, `core/estimateRequest.ts missingForRequest`)을 보여 준다.
- **보내면 잠김**: 보낸 요청은 견적 초안 방 설정 `estimateRequest {id,url,at}` 에 남고, 있으면 `app.consumerLocked` → `canEdit` false(보드를 못 고침). 상단 바는 [견적 요청] 대신 **🔒 견적 요청 중 · [요청 보기] · [요청 취소]**(`EstimateLock.svelte`, `estimate-locked`·`estimate-view`·`estimate-cancel`). 다른 기기·요청 페이지에서 취소했으면 열 때 서버 상태를 보고 잠금을 푼다.
- **취소 = 요청을 닫기만**(2026-10-22 사용자: "간판 사장들이 고객연락처를 먼저 받으면 취소 재요청은 필요없는것 같다" → "취소만 남기고 환불 재요청 빼줘"): `POST /api/requests/:id/cancel`(고객 키·세션, 열린 요청만) → `status = 'cancelled'`. 새 간판집 목록에서 빠지고 제안을 못 만든다. 이미 제안한 간판집은 연락처를 받았으므로 **제안 건수 환불 없음**, 목록에 **취소됨**(`request-cancelled`)과 메일 알림. 잠금이 풀려 보드를 고쳐 **새 요청**으로 보낸다(재요청·재견적 없음). 같은 날 먼저 넣었던 환불(`invites.refunded_at`)·재요청(`requests.prev_id`, 재견적 메일·태그)은 **대체됨** — 운영 DB 에 열은 남지만 쓰지 않는다.
- **요청 페이지**(`RequestView.svelte`): 배지(`request-badge` verified|general), 진행 단계(`request-steps`: 요청 접수 → 제안 도착 → 간판집 선택, `requestSteps`), 상태 카드(대기 중 깜빡임), 받은 제안, 요청 내용 요약(`request-summary`: 사인물·치수·사진·지역·내용), **[요청 취소]**(`request-cancel`) → 취소되면 **[고쳐서 새로 요청하기]**(`request-again`, /estimate).
- **사업자(여럿)**: 서버 `stores` 표(계정당 여럿, 국세청 진위확인 통과만 저장, 사본 R2 `stores/<id>/doc`). 요청에 `storeId` 를 실으면 번호·대표자·개업일·상태·사본이 요청에 복사된다(`biz_verified = 1`). 간판사 자신의 사업자(`businesses`, 계정당 하나)와는 따로.

## 요청 = 보드 복제, 간판집 가져오기 방식, 가게 사장 색 (2026-10-22)
사용자: "모바일 요청보기에 이미지가 올라오고 이미지 없어 … 이렇게 이미지로 만 올라오는데 그냥 요청시 페이지를 보여주는게 좋을 거 같은데 그리고 소비자용 페이지와 사업자용 컬러를 차이주고 싶은데 소비자용 페이지에 기존 노란색 말고 다른색으로" → "이미 서버에 이미지가 있는데 이중으로 작동한다. … 그 상태를 요청페이지로 복제해 놓는건 어떤가?" → "복제해서 자기 프로젝트로 가져오는건 옵션으로 보통 새로 만들경우도 있어서"

- **요청 = 견적 초안 방의 읽기 전용 복제**: 보낼 때 앱이 `fromProject`(내 견적 초안 방)를 싣고, 서버가 그 순간의 보드를 **요청 프로젝트**(`projects.kind = 'request'`, 소유 = 가게 사장, 이름 "<가게> 요청서")로 복제한다(`server/src/snapshot.ts cloneRoom` → `Room.cloneFrom`: photos·objects·sources·settings, 초안 설정 `estimate*` 와 대화는 뺌). **사진은 다시 올리지 않는다** — 에셋은 내용 해시 id 로 R2 에 하나라 새 소유 계정에 등록만(`account_assets`). `requests.snapshot_project`·`snapshot_photos`(사진 에셋 id). 전에는 휴대폰이 사진(장당 2~3MB)을 받아 요청 저장소에 또 올렸다. 옛 요청(복제 없음)은 예전 사진 방식 그대로.
- **요청 프로젝트는 읽기 전용**(`resolveAccess`): 가게 사장(소유)도 viewer, 그 요청을 볼 수 있는 간판집(지역·운영자·이미 제안함)도 viewer, 나머지 403. 대화·말풍선·승인 API 는 막는다(간판집끼리 섞이지 않게). 홈 목록에 안 나온다.
- **요청 페이지**에 **요청한 그대로**(`request-board`): 요청 프로젝트를 `?embed=1`(상단 바 없음)로 넣어 보여 주고 [크게 보기]. 사진 목록 대신. 사진 띠는 없앴다(2026-10-22 사용자 스크린샷: "여기 화면에 사진이 굳이 필요할까 사진필요 없다" — 옛 요청은 사진이 깨져 보였다).
- **간판집 받은 요청**(2026-10-22 사용자: "사업자는 페이지에서도 리스트는 이름 사인물 정보만 표시하고 클릭하면 복제된 페이지 바로보이게 해줘 그리고 견적넣기 버튼만 있으면 될거 같아"): 목록은 **가게 이름·배지·지역·사인물 수와 치수**(`request-signs`, 앞 3개)만, 썸네일·주소·사본·내용은 뺐다. 누르면 요청 프로젝트가 바로 열리고(`/?room=<요청 프로젝트>&request=<id>`) 위에 **요청 정보 줄**(`RequestBar.svelte`, `request-bar`: 가게·배지·주소·요청 내용·사업자등록증(견적 뒤 열림)) + **[견적 넣기]**(`request-respond`). 목록에도 같은 단추. 견적 넣기 = 요청 그대로(사진·사인물·치수) 내 프로젝트로 가져와 연다(`respond {mode: 'copy'}`). 같은 날 잠깐 두었던 [사진만]·[새로 만들기] 선택은 화면에서 뺐다(서버 `mode` 는 남음 — 지우고 새로 그리면 된다). 견적을 넣은 요청은 [내 견적 열기].
- **가게 사장 화면 색 = 청록**(`:root.consumer { --accent: #2dd4bf }`, `app.consumerTheme`): `/estimate`, 요청 페이지 `/r/…`, 그 안의 보드(`?c=1`). 간판집 화면은 노랑 그대로. 코드에 박혀 있던 노란색(`rgba(255,204,0,…)`·`#1a1500`)은 `var(--accent)`·`var(--accent-ink)` 로 바꿨다.

## 역할과 돈
| 역할 | 하는 일 | 돈 |
|---|---|---|
| 홍보자 | `/request?ref=<코드>` 링크·전단으로 가게 사장을 데려옴 | 자기 코드의 요청에 제안이 들어온 만큼(요금 발생분의 일부, 비율 미정). 간판다가 받은 돈 안에서 계좌이체 |
| 가게 사장 | 요청 올림(사진 1장 이상·가게·지역·내용·전화·이메일 선택). 요청 페이지에서 제안 비교·승인 | 무료 |
| 가입 간판사 | 설정에서 "요청 받기" + 지역. 홈 "받은 요청"에서 [제안 만들기] → 프로젝트 → 제안 링크 | **제안 링크를 만들 때** 요금제의 제안 건수(무료 월 3건, 베이직·프로 무제한). 제안을 보내야 고객 연락처가 보임 |

## 흐름
1. ~~**요청 올리기** `/request` (`RequestForm.svelte`)~~ → 2026-10-21부터 `/estimate` 소비자 보드(위). 옛 설명: 가게 이름(`req-store`), 지역(`req-region`, 시/군/구까지 — 간판사 지역과 글자 그대로 맞춤, 공백 무시), 원하는 내용(`req-text`), 전화(`req-phone`, 숫자만 9~11자리), 이메일 선택(`req-email`), 사진 1~3장(`req-photos`, 필수). `?ref=` 는 숨겨 저장. 보내면(`req-submit`) `POST /api/requests` → 사진 `PUT /api/requests/:id/photos?key=` → **내 요청 페이지 주소**(`req-done-link`, `/r/<id>?key=<키>`)를 보여 주고 "저장해 두세요", 이메일을 넣었으면 메일로도 보냄.
   - 같은 전화번호의 열린 요청이 3건이면 `429 request_limit` → "이미 3건의 요청이 진행 중입니다".
2. **간판사 알림**: 요청이 오면 그 지역의 "요청 받기" 간판사들에게 이메일(운영: Email Sending, 로컬: 건너뜀). 홈 **받은 요청**(`request-list`)은 프로젝트 위에 **"견적 요청 N"**(`request-toggle`·`request-count`, 답 안 한 건수)만 접혀 보이고 누르면 상세(`request-item`)가 펼쳐짐(2026-10-22 "프로젝트 위에 견적요청 + 수 표시하고 클릭하면 상세로"): 가게·지역·내용·날짜·사진. 연락처는 **제안을 보낸 요청에만**(`request-phone`).
3. **제안 만들기**(`request-respond`): `POST /api/requests/:id/respond` → 요청 사진이 들어갈 프로젝트(`projects.request_id`)가 생기고 그 방으로 이동. 앱은 방에 들어가 **문서에 사진이 없으면 요청 사진을 가져와 올립니다**(`importRequestPhotos`: 소유자 용량에 쌓임). 이미 만든 프로젝트가 있으면 그 방으로.
4. **제안 보내기**: 평소와 같음(`ProposalDialog`). 서버는 `request_id` 가 있는 프로젝트의 제안 링크를 만들 때 `request_responses` 에 기록(간판사·프로젝트·제안 주소) — 이것이 **요금 발생·홍보자 정산의 근거**이고, 이때부터 그 간판사에게 연락처가 보입니다.
5. **고객 요청 페이지** `/r/:id?key=` (`RequestView.svelte`, `request-page`): 요청 내용·사진·상태, 받은 제안 목록(`request-proposal`: 간판사 이름 · [제안 보기] → 제안 링크). 제안을 승인하면(기존 승인 흐름) 요청 상태가 **승인됨**(`requests.status = 'approved'`, 어느 간판사인지).
6. **요청 받기 설정**(`Settings.svelte` "요청 받기" 탭 `requests-section`, 요청판이 켜져 있을 때만): 켜기(`req-receive`) + 지역(`req-regions`, 쉼표로 여러 곳) → `PUT /api/me/request-settings`.

## 데이터 (D1, `server/migrations/0010_requests.sql`)
