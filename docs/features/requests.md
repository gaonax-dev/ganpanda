# 요청판 (견적 요청 → 가입 간판사 → 제안 링크)

## 요약
가게 사장이 **로그인 없이** 사진과 내용으로 간판 견적을 요청하면, 그 지역에서 **"요청 받기"를 켠 간판사**들에게 전달됩니다. 간판사는 요청에서 바로 프로젝트를 만들어(사진이 들어온 채로) 평소처럼 사인물을 그리고 **제안 링크**로 답합니다. 고객은 요청 페이지에서 받은 제안들을 나란히 보고 하나를 승인합니다. 계약·시공·돈은 고객과 간판사 사이에서 직접 — 간판다는 전달·기록만. 홍보자(아르바이트)는 자기 코드가 붙은 링크로 요청을 데려오고, 그 요청에 제안이 들어온 만큼 수수료를 받습니다(지급은 밖에서, 기록만). 결정 → [../product/decisions.md](../product/decisions.md) 2026-10-17, 과금 → [../product/pricing.md](../product/pricing.md).

- **제안 전 간판집에게 보이는 것**: 지역·층·사인물(치수·구성 리스트)·사업자 확인 배지·크레딧. **가게 이름·상세 주소·요청 내용·사업자번호·대표자·사본·사진은 가린다** — 서버가 목록에서 비우고(`lockedRequest`, `locked: true`), 알림 메일에도 지역·층·사인물 수·크레딧만(운영자 메일은 그대로), 요청 보드 이름도 "견적 요청서", 가져온 프로젝트 이름은 "<지역> <층> 요청". 카드 제목 = "<지역> <층> 요청", `request-floor`·`request-fee`.
- **사진**: 요청 보드(복제)의 사진 GET 은 가게 사장·**제안을 보낸 간판집**·운영자만(그 밖 403), 옛 요청 사진(R2)도 같다. [내 프로젝트로 가져오기]는 사진 자리·사인물·치수는 복제하지만 사진 파일 자격은 넘기지 않는다(`cloneRoom(…, copyAssets=false)`). 접근 정보 `photosLocked` → 앱은 사진 대신 **🔒 사진은 제안을 보내면 열립니다**(`photo-locked`), 리스트 카드 얼굴도 없음, 요청 보드는 **리스트로 바로 열린다**. 요청 정보 줄에 `request-lock-note`.
- **제안 링크를 만드는 순간**(`recordResponse`) 연락처와 함께 **사진이 열린다**(`unlockPhotos`: 요청 사진을 그 간판집 계정에 등록) — 가게 정보도 목록에 보인다. 운영자는 처음부터 다 본다.
- **결제 = 제안 링크를 만들 때**(2단계): 요청에서 가져온 프로젝트의 **첫 제안**에서 서버가 크레딧을 **등록 카드(빌링키)로 결제**(`billing.ts chargeCredit`, 주문명 "간판다 견적 요청 크레딧", `payments.kind = 'credit'`·`request_id` 0039) — 성공해야 제안 링크·사진·연락처가 열린다. 402 `card_required`(카드 없음 → 제안 창 [카드 등록하러 가기] `proposal-card`) · `credit_limit`(이번 달(한국 시각) 크레딧 합계 + 이번 금액 > **5,000,000원**) · `charge_failed`(카드사 거절). 같은 요청에 다시 제안해도 결제 없음, **요금제 월 제안 건수에 세지 않는다**, 운영자는 결제 없음. 제안 창에 금액 안내(`proposal-credit`, 접근 정보 `credit {fee, paid, on}`).
- **카드만 등록**: 설정 결제 칸 [카드만 등록](`billing-card-only` → 같은 토스 카드 등록, `plan: 'card'` = 구독 결제 없이 빌링키만). 구독 없이 카드가 있으면 "결제 카드 … 견적 요청 크레딧용" + [카드 바꾸기]. 결제 내역에 "견적 크레딧".
- **스위치 `REQUEST_CREDITS`**(wrangler vars): `"1"` 이면 실제 결제. **지금은 비워 둠** — 토스가 테스트 키(심사 중, 허용 목록 계정만 결제)라 켜면 간판집들이 제안을 못 보낸다. 꺼져 있으면 금액만 보이고 무료("지금은 정식 결제 전이라 무료"), 요금제 건수 규칙도 예전대로. 정식 키를 받으면 `"1"` 로 바꿔 배포.
- **토스페이먼츠 확인**: 포인트·크레딧 **충전형**은 환금성 상품으로 별도 심사·하루 10만원·1년 내 소진 등 제약(PortOne 안내) → 충전 대신 **자동결제(빌링키)로 쓴 만큼** 결제. 약관 제4조의5·환불 정책 1-2·요금제 페이지에 크레딧(청약철회 제한 — 결제와 동시에 요청 정보 제공, 이중 결제·오류·허위 요청은 환불).

## 간판집의 외주 요청 (B2B, 2026-10-22)
사용자: "사업자도 요청을 올릴수 있다. 해당 내역도 헤더에 표시. 프로젝트 카드 선택에 다른업체에 외주요청 버튼을 누르면 외주폴더로 이동한다. 이제 외주 리스트에서 프로젝트를 열면 기본컬러 핫핑크로 하고 요청 버튼이 생긴다. 해당 건은 b2b로 표시 보여준다"

- **외주 폴더**: 홈 프로젝트 ⋯ 속성창의 **[다른 업체에 외주 요청]**(`details-outsource`, 소유자만) → `PATCH /api/projects/:id {outsource: true}`(`projects.outsource`) → 홈의 **외주** 접이(`outsource-folder`, 핑크 제목)로 옮겨진다. 같은 단추가 [외주 해제]. **만들기에서 바로**: 새 프로젝트 칸을 누르면 펼쳐지는 줄 **맨 아래**의 **[다른 간판가게에 외주]** 체크(`new-outsource`, `POST /api/projects {outsource: true}`)로 처음부터 외주 폴더에 만든다(2026-10-22 "만들기에서 외주체크하면 바로 생성할 수 있다"; 2026-10-24 이름·자리 — "오해의 소지가 있으니 '다른 간판가계에 외주'로 표시 그리고 최하단에", 옛 이름 "외주 (B2B)").
- **외주 프로젝트를 열면 핫핑크**(`:root.outsource { --accent: #ff3d9a }`, access 응답 `outsource` — **소유자·팀(편집)에게만**, 고객(보기 초대·제안 링크)에게는 보내지 않아 핑크도 배지도 없다, 2026-10-24 "외주표시가 고객에게도 있다") + 상단 바 **B2B 외주** 배지(`outsource-badge`) + **[외주 요청]**(`outsource-request`) → 같은 대화식 요청 창(제목 "외주 견적 요청 (B2B)"). 간판집은 설정에서 확인한 **자기 사업자**(`est-account-pick`, 요청 `accountBusiness: true` → `businesses` 로 사업자 확인)나 등록한 사업자·일반 주문 중에서 고른다. 보내면 보드 복제(소비자와 같음) + `requests.b2b = 1`. 간판집 프로젝트는 **잠그지 않는다**(요청은 그 순간의 복제라 계속 고쳐도 됨) — 상단 바는 "외주 요청 중 · 요청 보기 · 요청 취소".
- **복제는 보드 배치만**: 요청 프로젝트·간판집 가져오기 모두 설정은 `flatScale·flatOffset·flatGap` 만 옮긴다(`DISPLAY_SETTINGS`). 단가표·원가·견적 줄·주문 정보는 절대 옮기지 않는다 — 외주 요청은 다른 간판집이 읽기 때문.
- **헤더 "보낸 요청 M"**(`request-sent-link`·`sent-count`, 진행 중인 내 요청 수, 보낸 요청이 있으면 보임) → `/requests?tab=sent`. 받은 요청 페이지(`/requests`) 안에서는 헤더의 "견적 요청 N"·"보낸 요청 M" 링크를 감춘다 — 페이지에 받은/보낸 탭이 있어 겹친다(2026-10-22 "견적요청 페이지에 견적요청 링크가 있는데 이건 감춰줘"). 받은 요청 페이지는 **받은 요청 / 보낸 요청** 탭(`inbox-tab-*`, `sent-item` → 요청 페이지). 내가 보낸 요청은 받은 목록에 나오지 않는다(서버가 뺌).
- **받는 쪽 B2B 표시**: 받은 요청 목록·요청 정보 줄·요청 페이지에 **B2B**(`request-b2b`). 외주 요청 페이지(`/r/…`)와 그 보드(`?o=1`)는 핫핑크, 받는 간판집이 여는 요청 보드는 노랑.

## 간판집 확정 (2026-10-22)
사용자: "소비자가 간판집을 제안 리스트에서 확정을 선택하면 견적요청에서 사라지고 탈락한 업체의 복제된 프로젝트에 배지를 달아 다른 곳에서 진행하게 된것을 알린다. 다만 변심으로 다시 시작할 수 있음으로 정지 처리 안내한다."

- **요청 페이지의 받은 제안마다 [확정]**(`request-choose`) → `POST /api/requests/:id/choose {projectId}`(고객 키·세션). 고른 제안에 **✓ 확정**(`request-chosen`), 요청은 승인됨(`requests.chosen_project`). 확정 뒤에도 다른 제안의 **[이 곳으로 바꾸기]**로 마음을 바꿀 수 있다. 제안 페이지에서 [이걸로 할게요]로 승인해도 같은 처리(`markApproved` → `chooseShop`).
- **받은 요청 목록에서 사라진다**(승인된 요청은 모든 간판집 목록에서 뺀다) — 고른 간판집은 자기 프로젝트에서 이어 간다.
- **떨어진 간판집 프로젝트**: `projects.lost_at` + **정지**(완료가 아니면) + 메일. 홈 카드에 **"다른 업체 선택"**(`project-lost`), 프로젝트를 열면 위에 안내(`project-lost-banner`: "다른 간판집과 진행하기로 했습니다. 마음을 바꿔 다시 연락할 수 있어 지우지 않고 정지로 두었습니다"). 가게 사장이 그 간판집으로 바꾸면 표시가 풀린다.

## 흐름
1. ~~**요청 올리기** `/request` (`RequestForm.svelte`)~~ → 2026-10-21부터 `/estimate` 소비자 보드(위). 옛 설명: 가게 이름(`req-store`), 지역(`req-region`, 시/군/구까지 — 간판사 지역과 글자 그대로 맞춤, 공백 무시), 원하는 내용(`req-text`), 전화(`req-phone`, 숫자만 9~11자리), 이메일 선택(`req-email`), 사진 1~3장(`req-photos`, 필수). `?ref=` 는 숨겨 저장. 보내면(`req-submit`) `POST /api/requests` → 사진 `PUT /api/requests/:id/photos?key=` → **내 요청 페이지 주소**(`req-done-link`, `/r/<id>?key=<키>`)를 보여 주고 "저장해 두세요", 이메일을 넣었으면 메일로도 보냄.
   - 같은 전화번호의 열린 요청이 3건이면 `429 request_limit` → "이미 3건의 요청이 진행 중입니다".
2. **간판사 알림**: 요청이 오면 그 지역의 "요청 받기" 간판사들에게 이메일(운영: Email Sending, 로컬: 건너뜀). **받은 요청**은 홈이 아니라 **헤더의 "견적 요청 N"**(`request-inbox-link`·`request-count`, 답 안 한 열린 요청 수, 요청 받기를 켰거나 운영자이거나 받은 요청이 있으면 보임, 2분마다 갱신 `app.refreshRequestCount`) → **받은 요청 페이지 `/requests`**(`RequestInbox.svelte`, `request-list`) — 2026-10-22 사용자: "견적요청표시가 메인에 있는데 헤더에 표시해도 될거 같아 그리고 페이지 이동해서 리스트 보이게" (그 전: 홈 프로젝트 위에 접힌 "견적 요청 N", 대체됨).
3. **제안 만들기**(`request-respond`): `POST /api/requests/:id/respond` → 요청 사진이 들어갈 프로젝트(`projects.request_id`)가 생기고 그 방으로 이동. 앱은 방에 들어가 **문서에 사진이 없으면 요청 사진을 가져와 올립니다**(`importRequestPhotos`: 소유자 용량에 쌓임). 이미 만든 프로젝트가 있으면 그 방으로.
4. **제안 보내기**: 평소와 같음(`ProposalDialog`). 서버는 `request_id` 가 있는 프로젝트의 제안 링크를 만들 때 `request_responses` 에 기록(간판사·프로젝트·제안 주소) — 이것이 **요금 발생·홍보자 정산의 근거**이고, 이때부터 그 간판사에게 연락처가 보입니다.
5. **고객 요청 페이지** `/r/:id?key=` (`RequestView.svelte`, `request-page`): 요청 내용·사진·상태, 받은 제안 목록(`request-proposal`: 간판사 이름 · [제안 보기] → 제안 링크). 제안을 승인하면(기존 승인 흐름) 요청 상태가 **승인됨**(`requests.status = 'approved'`, 어느 간판사인지).
6. **요청 받기 설정**(`Settings.svelte` "요청 받기" 탭 `requests-section`, 요청판이 켜져 있을 때만): 켜기(`req-receive`) + 지역(`req-regions`, 쉼표로 여러 곳) → `PUT /api/me/request-settings`.
